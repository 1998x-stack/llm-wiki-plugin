gsd-planner

概述

GSD 系统中的规划子智能体，负责基于研究结果生成 XML 结构化计划。它是整个 GSD 工作流中关键的架构决策环节。

关键内容

  1. 输入数据：
  2. PROJECT.md（技术约束和禁令）
  3. REQUIREMENTS.md（阶段必须实现的需求）
  4. CONTEXT.md（用户实现偏好决策）

  5. RESEARCH.md（四维研究结论）

  6. 核心职责：

  7. 综合所有输入，理解"需要做什么"和"如何做"
  8. 将工作分解为 2-3 个原子 XML 计划
  9. 每个计划控制在单个 200k 上下文可完成的规模内
  10. 分析计划间依赖关系，标记 <depends_on> 标签

  11. 确保垂直切片（每个计划是功能完整的端到端切片）

  12. 输出产物：

  13. N-01-PLAN.md, N-02-PLAN.md 等 XML 结构计划文件

  14. 计划间的依赖关系定义

  15. 模型分配策略：

  16. 在 balanced 模式下使用 Opus 模型，因为计划阶段是关键架构决策时刻

  17. 需要高质量的分解、任务边界定义和技术选型判断

  18. 工作特点：

  19. 串行执行（非并行）
  20. 需要精确的上下文构建
  21. 产出结构化的 XML 计划供执行器使用
