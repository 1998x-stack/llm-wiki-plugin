子 Agent 卸载（Subagent Offloading）

概述

子 Agent 卸载是上下文策略之一，将消耗大量 tokens 但只需要结论的操作（如运行测试套件、编译、截图分析）卸载给子 Agent 执行，主 Agent 仅接收精简的结论摘要，从而将主上下文的增长从数万 tokens 压缩到数十 tokens。

关键内容

  1. 核心机制：主 Agent 作为调度层保持精简，将 token 密集型操作 spawn 给子 Agent 执行。子 Agent 在执行层消耗大量 tokens 但不污染主上下文，最终返回简洁结论。例如：
  2. 主 Agent："请用子 Agent 运行完整测试套件，告诉我哪些通过，哪些失败"
  3. 子 Agent：执行 npm test → 生成 50,000 字符测试输出 → 总结为 "3 pass, 1 fail: auth.test.js line 45"

  4. 主上下文增加：~20 tokens（而非 50,000）

  5. 适合卸载的操作及 token 节省： | 操作 | 原始 tokens | 卸载后 tokens | 压缩比 | |------|------------|-------------|--------| | 运行完整测试套件 | ~50,000 | ~100 | 500:1 | | 编译大型项目 | ~20,000 | ~50 | 400:1 | | 截图分析 | ~8,000 | ~50 | 160:1 | | 文件树扫描 | ~10,000 | ~100 | 100:1 | | Git diff 大型变更 | ~30,000 | ~100 | 300:1 |

  6. 与 Orchestrator-Subagent-Pattern 的关系：子 Agent 卸载是 Orchestrator-Subagent 模式在上下文管理场景的具体应用。调度层（Orchestrator）负责决策和协调，执行层（Subagent）负责消耗性操作，两者通过精简的结论摘要通信。

  7. 设计原则：适合卸载的操作满足"消耗大量 tokens 但只需要结论"的特征。如果操作需要主 Agent 持续参与中间过程，则不适合卸载。
