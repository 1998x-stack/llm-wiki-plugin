探索-规划-编码工作流（Explore-Plan-Code Workflow）

概述

探索-规划-编码工作流是 Claude Code 推荐的四阶段开发方法论，将研究与规划同实现分离开来，避免在理解不充分的情况下解决错误问题。

关键内容

  1. 阶段 1：探索（Plan Mode）：读取目标代码区域，理解现有架构和实现方式。例如"读取 /src/auth 理解会话和登录处理方式，以及如何管理密钥的环境变量。"此阶段不修改任何代码，只做信息收集。

  2. 阶段 2：规划（Plan Mode）：基于探索结果，制定详细的修改计划。明确哪些文件需要修改、会话流程是什么、潜在的边界情况。在 Plan Mode 中可用 Ctrl+G 将计划在编辑器中直接编辑。规划的适用场景包括：不确定方法时、修改多个文件时、对要修改的代码不熟悉时。

  3. 阶段 3：实现（Normal Mode）：按计划执行代码变更，同时编写测试并运行测试套件验证。此阶段切换到 Normal Mode，允许实际的文件修改和命令执行。

  4. 阶段 4：提交（Normal Mode）：用描述性消息提交变更并开启 PR，完成整个工作流。

  5. 何时跳过规划：当能用一句话描述 diff 时（如修改拼写错误、添加日志行等简单变更），可以直接进入实现阶段，无需完整的探索-规划流程。

  6. 与 上下文窗口 的关系：分离探索与实现可以精确控制上下文内容——探索阶段在 Plan Mode 中累积的上下文不会影响实现阶段的 token 预算，体现了 上下文经济学 的核心思想。

  7. 与 子 Agent 模式（Sub-Agent Pattern） 的配合：探索阶段可以委托给子 Agent 在独立上下文中进行代码库调查，只将摘要返回给主对话，进一步减少主上下文的噪声。
