File Mapping

概述

在 writing-plans Skill 中的第一步关键活动，即在定义任何任务之前，先列出哪些文件将被创建或修改，以及每个文件的职责。这是锁定分解决策的地方，确保设计具有清晰边界和良好定义接口的单元。

关键内容

  1. 目的：
  2. 明确模块边界和文件职责
  3. 防止边写代码边拆分的混乱

  4. 在编码开始前就把架构想清楚

  5. 实施时机：

  6. 在 writing-plans Skill 定义任何任务之前
  7. 在 Design Document 已经批准之后

  8. 作为计划制定的首要动作

  9. 最佳实践：

  10. 小文件原则：更易推理、更可靠的编辑、高内聚性
  11. 单一职责：每个文件应该有一个明确的职责

  12. 相关文件共存：一起修改的文件应该住在一起（Cohesion）

  13. 输出结果：

  14. 创建文件列表：exact/path/to/file.py
  15. 修改文件列表：exact/path/to/existing.py:123-145

  16. 测试文件列表：tests/exact/path/to/test.py

  17. 与架构的关系：

  18. 文件映射是架构设计的具体体现
  19. 好的文件映射反映了清晰的模块划分
  20. 有助于后续的并行开发和测试
