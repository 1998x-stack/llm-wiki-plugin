prd.json 格式规范

概述

prd.json 是 PRD 驱动开发的核心数据文件，采用 JSON 格式定义项目的技术栈、User Story 列表、优先级、依赖关系和验收状态，作为 Agent 自主开发的权威任务源。

关键内容

  1. 顶层结构： json { "project": "项目名称", "version": "1.0.0", "created": "YYYY-MM-DD", "tech_stack": ["Next.js", "Prisma", "PostgreSQL"], "userStories": [...] }

  2. User Story 字段定义：

  3. id（必填）：唯一标识符，格式如 auth-001、ui-002，不可重复
  4. category：故事分类，用于组织和筛选
  5. title：Story 标题，简短描述
  6. description（必填）：以用户视角描述功能，"用户可以..." 而非 "实现..."
  7. acceptanceCriteria（必填）：验收标准数组，每个标准是可测试的具体条件
  8. passes（必填）：布尔值，仅验证通过后可设为 true
  9. priority（必填）：1-4 优先级，阻塞时可设为 99
  10. estimatedMinutes：估算实现时间，建议 30-90 分钟

  11. dependencies：依赖的 Story ID 数组，空数组表示无依赖

  12. 优先级规则：

  13. Priority 1：核心功能，项目无法运行的
  14. Priority 2：主要功能，用户主要使用的
  15. Priority 3：增强功能，让体验更好的
  16. Priority 4：边缘功能，可以最后做的

  17. Priority 99：阻塞降级，自动排到最低

  18. Story 分类体系：

  19. Authentication（认证）、User Profile（用户资料）、Core Feature（核心功能）
  20. API Integration（API集成）、UI/UX（界面交互）、Data Management（数据管理）
  21. Performance（性能优化）、Admin（管理后台）

  22. 专项场景：Landing Page、Billing、Email、Core Commands、Config Management、Core Endpoints、Data Validation、Rate Limiting、Testing 等

  23. 验收标准特殊要求：

  24. 前端/UI 相关 Story 的 acceptanceCriteria 必须包含 "Verify in browser using dev-browser skill"
  25. 每个 Story 可独立测试，不依赖未完成的 Story

  26. 如有依赖，必须在 dependencies 字段中明确标注

  27. 验证清单：

  28. 基本 JSON 格式合法性
  29. 每个 Story 的必填字段（id, description, acceptanceCriteria, passes, priority）
  30. 无重复 ID
  31. UI Story 包含 browser 验证步骤
  32. 优先级分布合理
  33. 分类覆盖完整
