子 Agent & 多 Agent 系统

概述

Claude Code 中的委派层，提供受控并行而非无限递归的 Agent 架构，通过深度限制防止 Agent 扩散失控。

关键内容

  1. 设计原则：
  2. 受控并行，而非无限递归
  3. 子 Agent 提供上下文隔离和并行能力

  4. 深度限制防止 Agent 扩散失控

  5. 为什么需要子 Agent：

  6. 主 Agent 上下文窗口有限（200k tokens）
  7. 并行探索多个实现方案
  8. 隔离执行重型探索（不污染主上下文）
  9. 专业分工（不同模型处理不同类型工作）

  10. 将工作委派给子 Agent，仅将结论返回主上下文

  11. 深度限制架构：

  12. 主 Agent -> Sub-Agent A（独立上下文，仅返回结论）
  13. 主 Agent -> Sub-Agent B（独立上下文，仅返回结论）
  14. 主 Agent -> Sub-Agent C（独立上下文，仅返回摘要）

  15. 严格禁止：Sub-Agent -> Sub-Sub-Agent（深度 > 1，阻断）

  16. Git Worktree 隔离：

  17. 子 Agent 在临时 Git Worktree 中执行
  18. 防止污染主工作目录
  19. 子 Agent 的实验性变更不影响主分支
  20. 多个子 Agent 可同时安全操作不同文件

  21. 子 Agent 完成后自动清理 Worktree

  22. 模型选择策略：

  23. 探索型（搜索、收集信息）：claude-haiku-4-5（廉价快速）
  24. 实现型（大多数编码）：claude-sonnet-4-6（平衡）

  25. 架构决策/深度推理：claude-opus-4-6（最强）

  26. 并行 Agent Teams 模式：

  27. 多个专业化 Agent 同时工作（安全、性能、架构评估）

  28. Validator 最终汇总，生成统一报告

  29. Builder-Validator 模式：

  30. Builder Agent 实现功能
  31. Validator Agent 验证实现
  32. 通过共享任务列表协调
