上下文传递协议

概述

上下文传递协议是 Harness 在会话交接时生成标准化上下文包的机制，确保 Agent 中断后恢复时能无缝继续工作，而非重新开始。

关键内容

  1. 标准化结构：上下文包包含五个核心部分——已完成功能列表、当前进行中功能（含进度百分比和子任务状态）、关键架构决策（含决策理由）、已知问题（带 ID 标记）、下一步行动计划。

  2. 架构决策记录：协议特别强调记录架构决策及其理由（如"使用 PostgreSQL 而非 SQLite（理由：生产环境考虑）"），这解决了长时开发中"为什么这样做"的知识流失问题。

  3. 已知问题追踪：每个已知问题都有唯一 ID（如 auth-bug-01、perf-01），包含问题描述和处理状态（如"已记录，暂缓"）。这确保问题不会在上下文切换时被遗忘。

  4. 与 上下文工程 的关系：上下文传递协议是 上下文工程 在长时 Agent 场景的具体实现，将抽象的上下文管理原则转化为可操作的标准化格式。

  5. 与 外化工作记忆 的关系：协议本质上是将 Agent 的工作记忆外化为持久化的 Markdown 文档，使得会话边界不再导致知识丢失。这是外化工作记忆概念在 Harness 工程中的直接应用。
