XML Plan System

概述

GSD 系统的结构化计划系统，使用 XML 标签定义任务，相比自然语言描述具有语义边界清晰、机器可处理、Claude 训练数据友好等优势，包含 8 维 plan-checker 验证机制。

关键内容

  1. 为什么 XML 比自然语言更适合：
  2. 语义边界清晰：标签创造硬性边界，消除猜测空间
  3. 训练数据友好：Claude 训练时见过大量 XML（API 文档、配置文件）

  4. 可机器处理：plan-checker 可靠解析任务列表、依赖关系

  5. XML Schema： xml <task type="auto|manual"> <n>任务名称</n> <files>涉及的文件路径</files> <depends_on>依赖的其他任务</depends_on> <action>具体执行指令（精确、可执行）</action> <verify>验证命令（会被真正执行）</verify> <done>完成的语义定义</done> </task>

  6. 标签职责：

  7. <n>：任务名称（也是 git commit message）
  8. <files>：精确文件路径，消除猜测
  9. <action>：必须实现的精确指令
  10. <verify>：Claude 会真正运行的命令
  11. <done>：完成的判断标准

  12. <depends_on>：依赖关系，用于 DAG 分析

  13. Plan-Checker 8 维验证：

  14. 需求覆盖完整性
  15. 技术一致性（与 PROJECT.md 约定）
  16. 计划原子性（单上下文可完成）
  17. 依赖关系正确性
  18. 并行安全性（同波次无文件冲突）
  19. 可验证性（<verify> 可执行）
  20. 上下文一致性（与 CONTEXT.md 决策）

  21. Nyquist 验证覆盖（测试合约）

  22. 文件命名：

  23. {phase}-{plan}-PLAN.md

  24. 例：02-01-PLAN.md（第 2 阶段第 1 个计划）

  25. 原子性原则：

  26. 每个 PLAN 文件包含 2-3 个任务
  27. 可在干净 200k 上下文窗口内完成
  28. 超过 150 个文件操作应拆分
