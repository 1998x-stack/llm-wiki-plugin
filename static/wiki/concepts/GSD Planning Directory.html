GSD Planning Directory

概述

GSD 系统的结构化项目记忆目录（.planning/），通过外部化项目记忆、按需加载不同文件子集，解决 LLM 上下文窗口限制和跨会话失忆问题。

关键内容

  1. 核心文件：
  2. PROJECT.md：项目愿景锚点（2-3 页，每次调用都加载）
  3. REQUIREMENTS.md：版本化需求边界（v1/v2/out-of-scope）
  4. ROADMAP.md：阶段路线图 + 状态追踪
  5. STATE.md：跨会话工程记忆
  6. CONTEXT.md：单阶段实现偏好（discuss-phase 生成）
  7. RESEARCH.md：阶段专属领域研究（plan-phase 生成）
  8. PLAN.md：原子执行计划（XML 格式）
  9. SUMMARY.md：执行存档

  10. VALIDATION.md：Nyquist 验证层（需求-测试映射）

  11. 特殊目录：

  12. research/：项目级领域研究
  13. seeds/：前瞻性想法（带触发条件）
  14. threads/：跨会话轻量知识存储
  15. todos/：待处理/已完成任务
  16. debug/：活跃调试会话
  17. codebase/：棕地代码库分析

  18. phases/：各阶段独立目录

  19. 文件加载策略： | 命令 | PROJECT | REQUIREMENTS | ROADMAP | STATE | CONTEXT | RESEARCH | PLAN | |------|---------|-------------|---------|-------|---------|----------|------| | new-project | - | 生成 | 生成 | 生成 | - | - | - | | discuss-phase | ✅ | ✅ | ✅ | ✅ | 生成 | - | - | | plan-phase | ✅ | ✅ | - | - | ✅ | 生成 | 生成 | | execute-phase | ✅ | - | - | - | - | - | ✅ |

  20. 设计哲学：

  21. 外部化项目记忆
  22. 结构化信息流
  23. 按需注入上下文
