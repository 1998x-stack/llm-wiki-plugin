# 游戏脚手架模式

## 概述
游戏脚手架模式是一种快速启动实践：为不同游戏类型预置完整可运行的[[骨骼系统|骨架]]代码，开发者只需选择合适模板并填充游戏逻辑，避免从零搭建重复样板。[[UrhoX引擎|UrhoX]] 提供四类 Lua 脚手架覆盖主流场景。

## 关键内容
1. **四类模板**：纯 2D 游戏（`scaffold-2d.lua`，无物理）；2D 物理游戏（`scaffold-2d-physics.lua`，内置 Box2D）；3D 场景展示（`scaffold-3d-scene.lua`，自由相机无角色）；3D 角色游戏（`scaffold-3d-character.lua`，第三人称角色控制）。
2. **使用约束**：任何新项目必须基于对应脚手架起手，禁止从零编写；多人/单机模式由 `.project/settings.json` 的 `multiplayer.enabled` 字段决定（`true` → Client.lua/Server.lua，`false` → Standalone.lua）。
3. **选择依据**：按游戏类型而非复杂度选择——Flappy Bird/Snake 等休闲游戏→ 2D；马里奥等平台跳跃→ 2D 物理；可视化/展示→ 3D 场景；Fall Guys/[[Roblox]] 风格→ 3D 角色；云变量/排行榜功能无需脚手架，直接用示例代码组合。
4. **复用示例的原则**：示例可作为起点，但交付前至少需要一轮优化（UI 美化、[[Configuration|配置]]调整、代码清理），不能直接复制交付；复制示例目录前须检查 `manifest.json` 是否定义了必需的附加文件（`.fsm`、`.blendspace`、[[Configuration|配置]] JSON 等）。
5. **模块化阈值**：单文件 < 1000 行可接受；1000–1500 行考虑拆分；> 1500 行必须拆分为多模块——参考 `examples/07-minecraft-voxel-world`（多文件架构示例）。
