# 权限模型

## 概述
权限模型定义了 AI Agent 在执行操作时如何获得、验证和行使系统访问权限，经历了从逐操作审批到授权范围定义的范式转变。

## 关键内容

1. **逐操作审批模型（旧）**：每次潜在危险操作都提示用户确认。存在三个核心问题：
   - 用户疲劳：长时间工作后用户机械批准，失去安全屏障意义
   - 工作流中断：频繁中断破坏 Agent 连续工作流
   - 权限粒度不匹配："允许所有文件操作"太宽泛，"逐一批准每个文件操作"太细粒度

2. **授权范围模型（新）**：会话开始时用户定义工作范围，沙箱保证范围内操作安全，Agent 在范围内自主工作。用户从"实时监督者"转变为"范围定义者"。

3. **三种操作分类**：
   - 完全沙箱内（无需审批）：项目文件读写、测试运行、包安装、git 操作
   - 需要一次性确认：访问项目外文件、新域名网络请求、系统级软件安装
   - 始终禁止：系统配置修改、密钥/凭证访问、非白名单服务数据发送

4. **与沙箱的关系**：权限模型定义了"什么可以做"的策略层，沙箱提供了"如何确保只做被允许的"的执行层。两者结合实现安全自主平衡。

5. **设计哲学**：安全即基础设施——将安全保证从用户持续监督转移到系统级执行约束，是 AI Agent 从工具走向可靠助手的必经之路。
