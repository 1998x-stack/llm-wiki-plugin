# 初始化-编码循环模式

## 概述
初始化-编码循环模式是 Agent Harness 设计中的核心架构模式，将长任务分解为"初始化"和"执行"两个分离的角色，通过外部进度文件实现状态传递和任务协调。

## 关键内容

1. **双角色分离**：
   - **Initializer Agent（初始化 Agent）**：
     - 理解完整任务的全貌和约束
     - 创建详细的任务规划文件（如 features.json）
     - 设定检查点标准和完成条件
     - 生成 claude-progress.txt 进度追踪文件
   - **Coding Agent（执行 Agent，可多实例）**：
     - 读取 claude-progress.txt 了解当前状态
     - 执行下一步具体任务
     - 更新进度文件反映完成状态
     - 提交可验证的检查点

2. **工作流程**：
   ```
   Initializer Agent → 创建 features.json + claude-progress.txt
   ↓
   Coding Agent 实例 1 → 读取进度 → 执行任务 → 更新进度 → 提交检查点
   ↓
   Coding Agent 实例 2 → 读取更新后的进度 → 继续执行 → ...
   ```

3. **设计优势**：
   - 初始化 Agent 专注于全局规划和约束设定
   - 执行 Agent 专注于当前步骤的具体实现
   - 多实例执行 Agent 可并行处理独立任务
   - 通过文件系统实现状态传递，不依赖对话历史

4. **与 Harness 的关系**：
   - 这是 [[Agent Harness 运行框架]] 的核心设计模式之一
   - 解决了长时任务中上下文窗口边界的根本挑战
   - 配合 [[外化进度追踪]] 和 [[检查点策略]] 共同工作
