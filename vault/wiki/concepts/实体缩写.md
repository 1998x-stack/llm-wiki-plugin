# 实体缩写

## 概述
实体缩写是 [[AAAK 方言]]中的核心压缩机制，通过在文档首次出现时建立实体到缩写的映射，后续全部使用缩写，在大规模重复实体场景下实现 30:1 的压缩比。

## 关键内容
- **工作机制**：当某个实体（人名、项目名、技术名）在文档中反复出现时，首次出现时建立缩写映射，后续全部使用缩写
- **映射示例**：`alice=A, bob=B, my_app=MAP, postgresql=PG, graphql=GQL`
- **Token 成本模型**：首次建立缩写的 token 开销是一次性的，之后每次使用都是极低代价
- **规模效应**：单条短文本中实体重复次数少，收益有限；在"重复实体的大规模场景"中才真正发挥 30:1 压缩优势
- **收益曲线**：压缩比随实体重复次数递增——0 次时约 1:1，5 次时约 5:1，20 次时约 10:1，100 次以上可达 30:1
- **与 [[Token 经济学]]的关系**：实体缩写是 [[Token 经济学]]在大规模场景下的核心收益来源
- **应用场景**：长期项目文档、团队讨论记录、技术决策日志等实体大量重复的积累场景
- **局限性**：在短文本、低实体重复的场景里，实体缩写可能不省 token 甚至更多（因为建立映射本身有开销）
