# 技术债务追踪

## 概述
技术债务追踪是 Harness 中记录和追踪技术债务的机制，确保在上下文切换时已知的质量问题不会被遗忘或丢失。

## 关键内容

1. **数据结构**：技术债务日志以表格形式记录，每条包含唯一 ID（如 TD-001）、问题描述、严重程度（高/中/低）、估计工作量和当前状态（待处理/已记录/处理中）。

2. **严重程度分级**：严重程度影响处理优先级。例如"认证竞争条件"标记为高（8h 工作量），"购物车 N+1 查询"标记为中（4h），"缺少 API 速率限制"标记为低（2h）。Harness 可根据严重程度自动提醒或升级。

3. **与 [[特性追踪器]] 的互补**：[[特性追踪器]]关注功能的开发进度，技术债务追踪关注已知的质量问题。两者共同构成完整的项目状态视图——一个管"做什么"，一个管"欠什么"。

4. **上下文切换不丢失**：Harness 的核心承诺是确保技术债务在上下文切换时不会丢失。每次 [[智能检查点触发]] 时，技术债务日志会随上下文包一起持久化，新会话的 Agent 能立即看到所有待处理债务。

5. **与已知问题的[[区分]]**：[[上下文传递协议]] 中的"已知问题"是当前开发中遇到的活跃 Bug（如 `auth-bug-01`），技术债务是架构或实现上的质量妥协（如 N+1 查询）。前者阻碍当前开发，后者影响长期质量。
