# 上游依赖变更

## 概述
上游依赖变更（Upstream Dependency Changes）指依赖的外部服务或数据源发生变更导致 Agent 行为异常的事故根因模式，LLM 对输入格式变化可能过度敏感是其特殊脆弱性。

## 关键内容

1. **定义与场景**：上游依赖变更是指系统依赖的外部服务、API 或数据源发生格式、结构或行为上的变更，导致下游 Agent 或 LLM 系统行为异常。典型场景包括：外部 API 返回格式变化、数据源 schema 更新、第三方服务行为变更等。

2. **AI 系统的特殊脆弱性**：LLM 对输入格式变化可能过度敏感，轻微的格式变化可能导致完全不同的输出。与传统软件中明确的类型检查和错误处理不同，LLM 可能"静默失败"——不报错但输出错误内容，这使得上游依赖变更在 AI 系统中更难检测。

3. **预防策略**：对关键数据源的格式变化做版本化检测，建立自动化监控和告警机制；在 Agent 输入层增加格式验证和规范化处理；维护上游依赖的变更日志和兼容性测试；对于 ACI（Agent-Computer Interface）场景，需要特别关注工具接口格式的稳定性。

4. **在 Postmortem 中的定位**：上游依赖变更是 Anthropic 事后回顾中识别的三类常见根本原因之一，与配置漂移、提示更新副作用并列。这类事故根因强调了 AI 系统对外部环境变化的敏感性。
