# 元控制框架（Meta-harness）

## 概述

元控制框架是一种不预设特定控制框架实现的系统设计模式，通过定义通用接口来容纳多种不同的 harness，使系统能随模型智能的提升而适配不同的控制框架需求。

## 关键内容

### 核心思想

> "Meta-harness 设计意味着对 Claude 周围的接口有主见：我们预期 Claude 需要操纵状态（会话）和执行计算（沙箱）的能力。但对 Claude 需要的大脑或手的数量和位置不做假设。"

元控制框架不对**具体**的 harness 有主见，而是对**围绕 Claude 的接口**有主见。

### 与 Agent Harness 模式的关系

| 维度 | [[Agent Harness模式]] | 元控制框架 |
|------|---------------------|-----------|
| 关注点 | 如何在现有框架上叠加能力 | 如何设计接口容纳多种 harness |
| 具体性 | 具体的[[ROS (Robot Operating System)|中间件]]栈和后端协议 | 抽象接口，不指定实现 |
| 演进 | 随模型能力增减组件 | 接口稳定，实现自由替换 |

### 设计哲学

类比操作系统：操作系统通过将硬件虚拟化为 `process`、`file` 等通用抽象而延续数十年。`read()` 命令不关心访问的是 1970 年代的磁盘组还是现代 SSD。抽象层保持稳定，底层实现自由变化。

元控制框架遵循同一模式：
- **会话**：抽象为可追加、可查询的事件流
- **沙箱**：抽象为 `execute(name, input) → string`
- **控制框架**：抽象为可调用的循环，可独立失败和重启

### 容纳的 Harness 类型

元控制框架可容纳：
- [[Claude-Code]]：优秀的通用 harness，广泛用于各类任务
- 领域特定的 Agent harness：在狭窄领域表现出色
- 未来可能出现的全新 harness 类型

### 工程意义

元控制框架解决了"如何为尚未想到的程序设计系统"这一经典计算问题。它使 Anthropic 能够在不破坏现有用户工作流的前提下，持续改进底层 Agent 实现。
