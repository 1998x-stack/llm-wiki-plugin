# 持续验证循环

## 概述
持续验证循环是 Harness 中代码修改后自动运行测试并进入修复循环的[[质量保障]]机制，确保每次代码变更都经过适当层次的验证。

## 关键内容

1. **验证流程**：Agent 修改代码 → 自动运行单测（快速）→ 通过则继续下一步 → 失败则自动进入修复循环（最多 3 次尝试）→ 超过 3 次失败则触发 [[三级自主权模型]] 级别 2 协议（请求人工确认）。

2. **多层次验证**：应用开发有多层次的正确性标准——语法正确性（代码是否编译）、单测通过（功能是否如期工作）、集成测试（组件交互是否正确）、端到端测试（用户流程是否完整）。Harness 需要在每个检查点运行适当层次的验证。

3. **与 [[Evaluator-Optimizer 模式]] 的关系**：持续验证循环是 [[Evaluator-Optimizer 模式]]的具体实现——Agent 是 Optimizer（生成代码修改），测试套件是 Evaluator（验证正确性），修复循环是优化迭代过程。

4. **快速反馈优先**：验证循环优先运行快速的单测，只有通过单测后才可能运行更耗时的集成测试或端到端测试。这确保 Agent 能在最短时间内获得反馈，减少资源浪费。

5. **自动修复限制**：修复循环最多尝试 3 次，超过后自动升级到人机协作协议。这防止 Agent 在顽固问题上无限循环消耗资源，同时确保问题得到适当的人工关注。
