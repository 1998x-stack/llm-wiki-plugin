# 冻结快照设计

## 概述
[[Hermes Agent]] 的 Prompt 组装策略：[[语义记忆|MEMORY.md]] 和 USER.md 在会话开始时捕获一次，整个会话期间不变，以保护 LLM 的 KV Cache 命中率。

## 关键内容
- **核心机制**：System Prompt 由 [[SOUL.md 人格系统|SOUL.md]]、[[语义记忆|MEMORY.md]]、USER.md、[[Agent Skills|Skills]] Level 0、Context Files、Active Tools、时间、平台元数据按顺序注入组装
- **冻结原因**：[[语义记忆|MEMORY.md]] 和 USER.md 在会话开始时捕获为冻结快照，会话期间不变 — 这不是疏忽，而是刻意权衡
- **KV Cache 保护**：冻结快照保证 [[Prompt 缓存|Anthropic Prompt Caching]] 的前缀稳定，大幅降低长期运行 Agent 的 Token 成本
- **记忆不一致性**：记忆文件在磁盘上实时更新，但下一次会话才会进入 Prompt — 这种"不一致"是保护缓存命中率的有意设计
- **Prompt 组成顺序**：[[SOUL.md 人格系统|SOUL.md]] → [[语义记忆|MEMORY.md]] → USER.md → [[Agent Skills|Skills]] Level 0 (~3k tokens) → Context Files → Active Tools → Date/Time → Platform Metadata
