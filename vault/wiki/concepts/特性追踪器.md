# 特性追踪器

## 概述
特性追踪器（Feature Tracker）是 Harness 的核心组件之一，以结构化 JSON 格式追踪功能的开发进度、子任务状态、测试用例、检查点和阻塞项。

## 关键内容

1. **数据结构**：每个特性包含唯一 ID、名称、状态（in_progress/complete/pending）、子任务列表、关联测试用例、检查点时间戳和阻塞项列表。子任务同样具有独立的 ID、名称和状态。

2. **测试关联**：特性追踪器将功能与具体测试用例直接关联（如 `test_auth.py::test_jwt_valid`），确保每个功能的完成都有对应的测试验证。这体现了"让测试充当接口"的实践原则。

3. **检查点集成**：每次特性完成或重要进展时，Harness 会记录检查点时间戳，形成可追溯的开发历史。这些检查点与 [[智能检查点触发]] 机制联动，在 `feature_complete` 事件时自动触发。

4. **阻塞项管理**：追踪器维护 `blockers` 数组，确保阻塞问题不会在上下文切换时丢失。这与 [[技术债务追踪]] 形成互补——阻塞项是当前开发的阻碍，技术债务是已知的质量问题。

5. **与项目管理工具的类比**：特性追踪器 ≈ 传统项目管理工具（如 Jira），但专为 AI Agent 设计，结构更轻量、与代码和测试直接关联，便于 Harness 自动读取和更新。
