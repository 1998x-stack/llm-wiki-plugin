# RAG项目90%从第一步就错了

## 概述
RAG 项目最常见的致命错误是在"检索环节"持续优化，而忽视根源问题——数据分块设计。文档分块本质上是把完整知识体系强行撕裂，块与块之间的逻辑关联和层级关系被打碎，导致多跳推理和跨章节关联的复杂问题准确率腰斩。解决思路是从自下而上的 GraphRAG 转向自上而下的知识图谱树构建。

## 关键内容
1. **核心教训**：90%的RAG项目在数据分块环节就埋下隐患，后续检索优化无法弥补
2. **失败模式**：简单单点问题准确率高，多跳推理/跨章节关联问题准确率腰斩
3. **无效优化**：给大模型加 reflection 反思机制、多轮迭代检索循环，效果有限
4. **正确路径**：自上而下构建知识图谱树，还原知识原生框架（目录→章节→知识单元）
5. **落地四步**：框架提取 → 知识单元拆解 → 图谱树合并 → 检索逻辑重构
6. **通用方法论**：把无序信息变成有序、可检索、可推理的结构化知识

## AI落地四条底层真相
1. **模型选型**：榜单分数不如业务适配重要，稳定性、合规性、成本优先
2. **微调误区**：绝大多数场景微调性价比极低，小样本微调易导致通用能力塌方
3. **工程师核心能力**：不再是手写代码，而是拆解业务、设计架构、定义规则、给AI提精准需求
4. **跨行业落地**：核心是可复制的底层逻辑，不是定制化功能
