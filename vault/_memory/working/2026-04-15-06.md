# Session: v3.3 系统级重构 — 共享模块 + Qwen 管线 + QA 统一

## 观察

- **O1: 代码重复是系统性的，不是偶然的** — 6 个独立 parse_frontmatter 实现（regex/find/yaml 行为不一致）。根因：脚本在不同时间点独立开发，无共享模块。创建 wiki_utils.py 一次消除。启示：当脚本超过 5 个时，共享模块不是优化而是必须。

- **O2: Qwen 管线的核心缺陷是无状态性** — Claude 引擎上下文感知（读 index、检查已有页面、合并），Qwen 引擎是纯 fire-and-forget。通过 --context-pages 注入已有页面列表 + scan_existing_pages() 本地去重桥接差距。模式：外部 API 调用需要"上下文补偿层"。

- **O3: 错误容忍 vs 错误拒绝是架构决策** — 原 qwen_ingest 跳过 YAML 错误页面 = 静默丢数据。新设计：总是输出 + 附带 errors 字段 + error.md 持久日志。原则：入口宽容、后续修复优于入口严格、数据丢失。

- **O4: QA 管线有两个孤立的数据流** — wiki:query → qa/（从不被读取），wiki:qa-import ← raw/qa/（从不被写入）。统一为 wiki:query → raw/qa/ → qa.snapshot.md → wiki:qa-import。qa/ 文件夹删除。模式：write 和 read 路径必须对齐。

- **O5: hook_graph 全量重建是隐性 O(N) 开销** — 每次 wiki 编辑触发 build_graph.py 读取 188 个文件。30s mtime 防抖是最小侵入修复。模式：hooks 成本随数据量线性增长，需定期审计。

- **O6: 有向图边去重丢失语义方向** — sorted([src,tgt]) 键对 contradicts/supersedes/extends 丢失方向。修复：有向关系用 (src,tgt,rel) 键。模式：数据结构的去重策略必须与语义匹配。
