## 一、MinerU 是什么？解决了什么问题？

### 1.1 问题的根源

PDF（Portable Document Format）是当今学术与工业界最主流的文档格式。然而 PDF 本质上是一种**"打印指令集"**，而非语义结构化数据格式。每一个字符、每一条线段，在 PDF 内部都被存储为带坐标的图元（glyph/path），完全**没有**"这是标题"、"这是公式"、"这是表格"这样的语义信息。

这导致：
- **直接文本提取**（如 `pdfminer`、`PyMuPDF`）得到的是乱序的字符流，多栏布局、脚注、侧边栏全部混在一起
- **图像化 PDF**（扫描件）根本没有文字层，纯靠 OCR
- **公式**以图像形式存储，无法直接转成 LaTeX
- **表格**的单元格边界仅靠线条暗示，结构难以还原

大语言模型（LLM）时代到来后，高质量的文档解析变得格外重要——RAG 系统、知识库构建、文档问答，全都依赖**精准的文本提取**。MinerU 正是为填补这个空白而生。

### 1.2 MinerU 的核心设计目标

| 目标 | 具体含义 |
|------|---------|
| **高保真还原** | 公式转 LaTeX，表格转 Markdown 表格，图注保留 |
| **阅读顺序正确** | 多栏、脚注、侧边栏按人类阅读顺序排列 |
| **格式无关** | 支持文字型 PDF 和扫描件（OCR）两种管道 |
| **可扩展输出** | 导出 Markdown、JSON（带 bbox 坐标）、多模态格式 |
| **工业级鲁棒性** | 能处理数千页的大型 PDF，不崩溃 |

## 二、整体架构：七层流水线

MinerU 的核心处理逻辑是一条**串行流水线（Pipeline）**，按以下七个阶段逐层处理：

```
┌─────────────────────────────────────────────────────────┐
│                    输入：PDF 文件                        │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│  第一层：PDF 类型判断 & 后端选择                         │
│  (TextBased / OCRBased / MixedBased)                    │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│  第二层：底层 PDF 解析                                   │
│  PyMuPDF 提取原始 Span/Block + 页面渲染为图像            │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│  第三层：文档布局检测（Layout Analysis）                  │
│  DocLayout-YOLO / LayoutLMv3 → 检测文本区/图/表/公式框   │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│  第四层：内容专项识别                                    │
│  ├── OCR（PaddleOCR）：识别文本区文字                   │
│  ├── 公式识别（UniMERNet）：检测框 → LaTeX              │
│  └── 表格识别（TableMaster）：检测框 → 结构化表格       │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│  第五层：内容块分类与属性标注                            │
│  title / text / figure / table / formula / ...          │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│  第六层：阅读顺序排序（Reading Order）                   │
│  基于坐标与分栏分析，重建人类阅读序列                    │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│  第七层：Markdown / JSON 内容生成                        │
│  将有序内容块序列化为目标格式                            │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│           输出：Markdown + JSON + 图片资源               │
└─────────────────────────────────────────────────────────┘
```

## 三、两条核心管道：TextPDF vs OCRPDF

MinerU 在启动时首先**判断 PDF 类型**，然后走不同的处理管道：

### 3.1 TextBased 管道（文字型 PDF）

```
PDF → PyMuPDF 提取字符坐标 → Layout 检测 → 
内容识别（OCR可选） → 顺序排列 → 输出
```

适用于：数字原生 PDF（LaTeX 生成、Word 导出等），文字层完整。PyMuPDF 可以直接读取到精确到亚像素的字符坐标，不需要 OCR。

### 3.2 OCRBased 管道（扫描件 PDF）

```
PDF → 页面渲染为图像 → Layout 检测 → 
PaddleOCR 全量识别 → 内容识别 → 顺序排列 → 输出
```

适用于：扫描件、图像型 PDF，没有任何文字层。所有文字都需要 OCR 识别。

### 3.3 混合管道（Mixed）

部分 PDF 既有文字层又有图像区域，MinerU 逐页判断，分别走对应管道。

## 五、核心数据结构：PDFPageInfo

MinerU 在整个管道中流转的核心数据结构是 **`PDFPageInfo`**，它代表单页的全部解析结果：

```python
class PDFPageInfo:
    page_no: int                    # 页码
    width: float                    # 页面宽度（pt）
    height: float                   # 页面高度（pt）
    
    # 原始解析层
    raw_spans: List[Span]           # PyMuPDF 提取的原始字符组
    images: List[ImageBlock]        # 嵌入图像
    
    # 布局检测结果
    layout_bboxes: List[LayoutBox]  # 检测到的布局框（带类别标签）
    
    # 识别结果
    para_blocks: List[ParaBlock]    # 段落文本块
    table_blocks: List[TableBlock]  # 表格块（含结构）
    formula_blocks: List[FormulaBlock]  # 公式块（含 LaTeX）
    figure_blocks: List[FigureBlock]    # 图像块（含图注）
    
    # 排序后的最终序列
    sorted_blocks: List[ContentBlock]   # 按阅读顺序排列的内容块
```

这个数据结构贯穿整个管道，每一层往其中填充不同的字段，最终 `sorted_blocks` 就是生成 Markdown 的直接来源。

## 六、与同类工具的对比

| 特性 | MinerU | pypdf / pdfminer | Marker | Nougat |
|------|--------|-----------------|--------|--------|
| **文字型 PDF** | ✅ 高质量 | ✅ 但乱序 | ✅ | ✅ |
| **扫描件** | ✅ OCR管道 | ❌ | ✅ | ✅ |
| **公式 → LaTeX** | ✅ UniMERNet | ❌ | ⚠️ 有限 | ✅ |
| **表格结构** | ✅ TableMaster | ❌ | ⚠️ | ❌ |
| **阅读顺序** | ✅ 多栏支持 | ❌ | ✅ | ✅ |
| **开源** | ✅ Apache-2.0 | ✅ | ✅ GPL | ✅ |
| **速度** | 中（模型推理） | 快 | 中 | 慢 |
| **中文支持** | ✅ 极佳 | ⚠️ | ⚠️ | ❌ |

MinerU 的最大差异化优势在于：**中文文档支持**（PaddleOCR 中文能力）+ **公式/表格专项识别**的组合，这是其他工具难以同时具备的。
