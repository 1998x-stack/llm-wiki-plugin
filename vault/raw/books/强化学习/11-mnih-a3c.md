# 11 | Mnih et al.《Asynchronous Methods for Deep Reinforcement Learning》(2016)

## A3C：异步训练革命与Actor-Critic的现代复兴

## 2. 一句话总结

**通过让多个 actor-learner 线程在各自的环境副本中并行交互并异步更新共享参数，A3C 以极低的计算成本（单台多核 CPU）实现了超越 DQN 的性能，同时复兴了 Actor-Critic 方法并为后续分布式强化学习奠定了基础范式。**

## 3. 当时的时代问题

2015 年，DQN（Deep Q-Network）在 Nature 上的发表标志着深度强化学习的正式诞生。DQN 首次证明了深度神经网络可以直接从原始像素输入学习控制策略，在 Atari 2600 游戏上达到了人类水平。然而，DQN 的成功背后隐藏着沉重的工程代价和理论局限。

**DQN 的核心瓶颈有三个方面：**

第一，**经验回放（Experience Replay）的内存开销**。DQN 依赖一个巨大的回放缓冲区（通常存储 100 万个转移样本）来打破数据之间的时间相关性。每个样本包含完整的游戏帧（84x84 像素），这意味着仅回放缓冲区就需要数 GB 的 RAM。在资源受限的环境下，这是一个严重的瓶颈。

第二，**GPU 计算的高成本**。DQN 的训练需要在高端 GPU 上运行数天甚至数周。2015-2016 年间，单块高端 GPU 的价格在数千美元，而训练一个 Atari 游戏的智能体通常需要持续占用一块 GPU 好几天。这使得深度 RL 研究成为少数有大量计算资源的实验室的"专属领地"。

第三，**算法适用范围的狭窄**。经验回放要求算法必须是 off-policy 的（即可以从旧策略生成的数据中学习），这直接排除了 on-policy 方法，如 SARSA、Actor-Critic 等。而这些 on-policy 方法在理论上具有更好的收敛性质，在连续控制等任务上往往表现更优。DQN 的框架本质上将整个 on-policy 方法家族拒之门外。

**时代之问由此浮现**：能否找到一种不依赖经验回放的去相关化方法？能否让深度 RL 训练摆脱对昂贵 GPU 的依赖？能否构建一个统一的框架，同时适用于 on-policy 和 off-policy 算法？

当时已有一些平行探索。Gorila（General Reinforcement Learning Architecture）使用分布式架构在多台机器上并行训练 DQN，但其仍然依赖经验回放，且需要大量机器。Nair 等人的工作证明了并行化的潜力，但未能摆脱 replay buffer 的桎梏。A3C 的核心洞察在于：**并行化本身就是一种去相关化机制**——不同 actor 在不同环境中、处于不同状态、经历不同轨迹，它们产生的梯度天然具有多样性，无需额外的回放缓冲区即可稳定训练。

## 4. 核心问题定义

本文要解决的核心问题可以精确表述为：

**如何设计一种通用的异步训练框架，使其（1）通过并行化自然地打破数据相关性，从而替代经验回放；（2）能够适用于多种 RL 算法（包括 on-policy 和 off-policy）；（3）在普通多核 CPU 上即可高效运行，大幅降低训练的硬件门槛？**

这个问题的定义本身就是深思熟虑的结果。论文没有把自己限定在某一个具体算法上，而是提出了一个**框架级别**的解决方案。作者试图证明：异步并行化是一种适用于广泛 RL 算法的通用训练加速范式，而不仅仅是某个特定算法的技巧。

从技术角度看，核心挑战在于：多个 learner 线程异步地更新同一组共享参数时，如何保证训练的稳定性和收敛性？不同线程读取参数和写入梯度之间存在时间差（staleness），这会导致所谓的"旧梯度问题"（stale gradient problem）。论文需要证明，在实践中这种异步更新不仅不会导致训练崩溃，反而能通过梯度的多样性带来正则化效果，提升训练的稳定性。

## 5. 核心方法与思想

### 5.1 异步训练框架的总体架构

A3C 的训练架构在概念上极为简洁。想象一台多核 CPU 的机器，每个核心上运行一个独立的"actor-learner"线程。每个线程拥有：

- **自己的环境副本**：线程 $i$ 运行自己的游戏/环境实例
- **自己的网络副本**：包含本地参数 $\theta'_i$，定期从全局参数 $\theta$ 同步
- **自己的梯度累积器**：在本地计算若干步的梯度后，异步地更新到全局参数 $\theta$

关键在于"异步"二字：各线程独立运行，互不等待。线程 A 不必等待线程 B 完成更新后才能读取参数。全局参数的更新是无锁的（lock-free），依赖于 CPU 的原子操作来保证基本的写入一致性。

这种架构的精妙之处在于：不同线程的环境处于完全不同的状态——线程 1 可能在游戏的第 100 帧，线程 2 可能在第 2000 帧，线程 3 可能刚刚重置。它们产生的梯度来自不同的状态分布，天然地具备多样性，无需人为的随机采样即可打破数据之间的时间相关性。

### 5.2 四种异步变体

论文提出了四种异步变体，展示了框架的通用性：

**（1）Asynchronous one-step Q-learning**：每个线程运行标准的 one-step Q-learning，在每一步之后用 $(s, a, r, s')$ 计算 TD 误差并更新全局 $Q$ 网络。仍然使用 $\epsilon$-greedy 探索，但不同线程使用不同的 $\epsilon$ 值以增加探索多样性。

**（2）Asynchronous one-step SARSA**：与 Q-learning 类似，但使用 on-policy 的 SARSA 更新规则。这是一个重要的实验，因为 SARSA 作为 on-policy 方法在 DQN 框架中无法使用经验回放，但在异步框架中自然适用。

**（3）Asynchronous n-step Q-learning**：每个线程累积 $n$ 步的经验 $(s_t, a_t, r_t, \ldots, s_{t+n})$，计算 n-step return $R_t = r_t + \gamma r_{t+1} + \ldots + \gamma^{n-1} r_{t+n-1} + \gamma^n \max_a Q(s_{t+n}, a)$，然后一次性更新。n-step return 在 bias 和 variance 之间取得了更好的平衡。

**（4）Asynchronous Advantage Actor-Critic（A3C）**：这是论文的核心贡献，也是表现最好的变体。它结合了 Actor-Critic 架构、n-step return 和优势函数。

### 5.3 A3C 的核心设计

A3C 的网络架构采用**共享参数**的设计：一个神经网络同时输出策略 $\pi(a|s;\theta)$（actor 头）和价值函数 $V(s;\theta_v)$（critic 头），底层的卷积层和全连接层在二者之间共享。这种参数共享不仅减少了计算量，还使得特征表示能够同时服务于策略优化和价值估计，实现了隐式的辅助学习。

**优势函数（Advantage Function）** 是 A3C 的核心概念：

$$A(s_t, a_t) = Q(s_t, a_t) - V(s_t)$$

优势函数衡量的是：在状态 $s_t$ 下选择动作 $a_t$ 比"平均水平"好多少。使用优势函数而非原始回报作为策略梯度的权重，可以显著降低梯度估计的方差（variance），从而加速收敛。

在实践中，$Q(s_t, a_t)$ 不直接估计，而是用 n-step return 来近似：

$$R_t = r_t + \gamma r_{t+1} + \ldots + \gamma^{n-1} r_{t+n-1} + \gamma^n V(s_{t+n};\theta_v)$$

于是优势函数的估计变为：

$$A(s_t, a_t) = R_t - V(s_t;\theta_v)$$

这实际上就是 n-step TD 误差，同时也等价于广义优势估计（GAE）在 $\lambda = 1$ 时的特殊情况。

**策略梯度更新规则**：

$$\nabla_\theta \log \pi(a_t|s_t;\theta) \cdot A(s_t, a_t)$$

**价值函数损失**：

$$L_v = (R_t - V(s_t;\theta_v))^2$$

### 5.4 熵正则化

A3C 引入了一个精巧的正则化项——策略的熵（entropy）：

$$H(\pi(s_t)) = -\sum_a \pi(a|s_t) \log \pi(a|s_t)$$

这个熵项被加入到目标函数中（带一个系数 $\beta$），鼓励策略保持一定的随机性，防止过早收敛到次优的确定性策略。这种**熵正则化（entropy regularization）** 后来成为了几乎所有策略梯度方法的标准配置，在 SAC（Soft Actor-Critic）等后续工作中被进一步发展为"最大熵强化学习"的核心思想。

### 5.5 异步更新替代经验回放

A3C 彻底放弃了经验回放机制。传统观点认为，深度 RL 需要经验回放来：

1. **打破数据相关性**：连续的经验在时间上高度相关，直接用于训练会导致网络过拟合于当前状态附近的数据分布。
2. **提高数据效率**：每个经验可以被多次使用。

A3C 用异步并行化替代了第一个功能：多个线程处于不同的环境状态，自然地产生去相关的训练数据。至于第二个功能（数据效率），A3C 选择了一条截然不同的哲学路线——**用更快的数据生成速度来弥补数据利用效率的损失**。多个线程同时产生经验，总吞吐量远高于单线程，因此即使每条经验只使用一次，训练速度仍然很快。

### 5.6 与 DQN 的对比

| 维度 | DQN | A3C |
|------|-----|-----|
| 去相关化方式 | 经验回放 | 异步并行 |
| 策略类型 | Off-policy（Q-learning） | On-policy（Actor-Critic） |
| 输出 | 动作价值 Q(s,a) | 策略 $\pi(a\|s)$ + 价值 V(s) |
| 动作空间 | 仅离散 | 离散 + 连续 |
| 硬件需求 | GPU + 大内存 | 多核 CPU |
| 内存开销 | 高（回放缓冲区） | 低（无缓冲区） |
| 探索策略 | $\epsilon$-greedy | 策略随机性 + 熵正则化 |

## 6. 创新点

**创新点一：异步并行化作为通用去相关化机制**。论文最根本的贡献不是某个具体算法，而是一个洞察：并行化本身就足以替代经验回放来稳定深度 RL 训练。这个洞察改变了整个领域对"如何训练深度 RL"的认知框架。在此之前，经验回放被视为深度 RL 的"必需品"；在此之后，它变成了众多可选方案之一。

**创新点二：Actor-Critic 在深度学习时代的首次成功**。虽然 Actor-Critic 方法在理论上已存在数十年（Konda & Tsitsiklis, 2000），但在深度神经网络中一直被认为不稳定、难以训练。A3C 首次证明了深度 Actor-Critic 不仅可行，而且效果优于深度 Q-learning，彻底复兴了这一算法家族。

**创新点三：共享网络的 Actor-Critic 架构**。将策略网络和价值网络统一为一个共享底层特征的网络，既减少了参数量，又通过多任务学习的效应提升了特征质量。这种设计成为后续 Actor-Critic 方法的标准架构。

**创新点四：熵正则化的系统化使用**。虽然熵奖励在 RL 中并非全新概念，但 A3C 将其系统化地整合到策略梯度框架中，证明了它对防止过早收敛的关键作用，催生了后续的最大熵 RL 研究方向。

**创新点五：CPU 训练的可行性**。在 GPU 加速被视为深度学习"标配"的时代，A3C 反潮流地证明了单台多核 CPU 机器即可训练出世界级的 RL 智能体。16 个 CPU 核心上的 A3C 在训练时间和最终性能上都优于使用 GPU 的 DQN，这极大地降低了深度 RL 研究的硬件门槛。

**创新点六：n-step return 的实际有效性验证**。n-step return 在理论上早已被研究（Sutton, 1988），但 A3C 在大规模实验中系统性地验证了其在减少偏差方面的实际价值，使其成为后续工作的标准配置。

## 7. 结果、实验与验证

### 7.1 Atari 2600 游戏

论文在 57 个 Atari 2600 游戏上进行了全面评估。A3C 使用 16 个线程、在单台多核 CPU 机器上训练，结果令人振奋：

- **性能**：A3C 在大多数游戏上达到或超过了 DQN 的表现。在 57 个游戏中，A3C 在超过一半的游戏上优于 DQN 和其他基线方法（如 Dueling DQN、Double DQN 等）。
- **训练效率**：A3C 在训练时间上实现了数量级的提升。以 Atari 游戏为例，DQN 通常需要在 GPU 上训练 8-10 天，而 A3C 在 16 核 CPU 上仅需约半天至一天即可达到相当的性能水平。
- **线性加速**：论文展示了近乎线性的加速比——16 个线程比单线程快约 16 倍，证明了异步框架的高效可扩展性。

### 7.2 训练时间的大幅缩短

这是论文最引人注目的实验结果之一。在 Atari 基准上，A3C 用 16 个 CPU 核心训练 1 天的效果，就超越了 DQN 用 1 块 GPU 训练 8 天的效果。换算成实际时钟时间，训练效率提升了约 8-10 倍，而硬件成本却大幅降低（一台多核 CPU 服务器的价格远低于配备高端 GPU 的工作站）。

更重要的是，论文展示了训练速度与线程数之间近乎线性的关系。每增加一个训练线程，总体训练速度几乎等比例提升，说明异步更新带来的"旧梯度"问题在实践中的影响远小于理论上的担忧。

### 7.3 TORCS 赛车与连续控制任务

A3C 不仅在离散动作空间的 Atari 游戏上表现出色，还在连续控制任务上展示了强大的能力。论文在 TORCS 3D 赛车模拟器上训练了 A3C 智能体，直接从像素输入学习驾驶策略，输出连续的方向盘角度和油门/刹车力度。智能体在仅 12 小时的训练后即学会了基本的赛道驾驶技巧。此外，论文还在 MuJoCo 物理模拟器中的多个连续控制任务上进行了测试，包括多关节机器人运动等，A3C 均展现了竞争力。这一结果尤为重要，因为 DQN 由于其离散动作空间的限制，根本无法直接应用于这些任务。

### 7.4 3D 迷宫导航（Labyrinth）

论文还在一个第一人称视角的随机 3D 迷宫中测试了 A3C。在这个任务中，智能体需要从原始像素输入出发，在随机生成的迷宫中导航到目标位置。这个任务的挑战在于：（1）部分可观测性——智能体只能看到第一人称视角的画面；（2）长期规划需求——需要记住已探索的区域并制定探索策略。A3C 结合 LSTM 成功学会了基本的探索和导航策略，而不使用 LSTM 的前馈版本则表现显著下降，这验证了在部分可观测任务中引入记忆机制的必要性。

### 7.5 异步方法之间的对比

在四种异步变体中，A3C 一致性地表现最优。异步 n-step Q-learning 表现次之，异步 one-step Q-learning 和 SARSA 表现相对较弱。这一结果说明：（1）Actor-Critic 架构在与异步框架结合时具有天然优势；（2）n-step return 带来的偏差减少确实转化为了更好的实际性能。

## 8. 局限性

**局限一：旧梯度问题（Stale Gradient Problem）**。异步更新的本质意味着每个线程计算梯度时使用的参数可能已经过时——在计算完成之前，其他线程可能已经更新了全局参数若干次。虽然论文通过实验证明这在 16 个线程的规模下并不会严重影响性能，但随着线程数的增加（例如扩展到数百或数千个 worker），旧梯度问题会显著恶化，导致训练不稳定甚至发散。这一问题后来由 IMPALA 通过 V-trace 修正机制得到了更系统的解决。

**局限二：数据效率（Sample Efficiency）偏低**。A3C 作为 on-policy 方法，每条经验只使用一次就被丢弃。虽然它通过并行化弥补了数据利用率的不足，但在交互成本高昂的场景（如真实机器人学习）中，这种策略并不理想。后续的 off-policy Actor-Critic 方法（如 SAC、ACER）在数据效率上有显著改进。

**局限三：超参数敏感性**。A3C 的性能对若干超参数（如 n-step 长度、熵正则化系数 $\beta$、学习率等）较为敏感。不同的 Atari 游戏往往需要不同的超参数设置才能达到最佳性能，这限制了其作为"通用算法"的实用性。

**局限四：训练的不可复现性**。由于异步更新的非确定性（线程调度顺序不可预测），A3C 的训练过程本质上是不可精确复现的。同样的超参数和随机种子在不同运行中可能产生不同的训练曲线和最终性能。这在需要严格实验对比的研究场景中是一个缺点。后来的 A2C（Advantage Actor-Critic，同步版本）通过牺牲一部分效率来换取可复现性，在很多研究中被更多采用。

**局限五：缺乏 off-policy 修正**。虽然 A3C 在理论上是 on-policy 的，但异步更新实际上引入了轻微的 off-policy 性质（因为行为策略与学习策略之间存在延迟）。论文没有对这种偏差进行任何修正，后续的 IMPALA（Importance Weighted Actor-Learner Architecture）通过引入重要性采样比率和 V-trace 目标显式解决了这个问题。

**局限六：扩展性的天花板**。A3C 的设计适用于单机多线程，但在跨机器的分布式场景中，线程间共享内存的假设不再成立，需要网络通信来同步参数，这引入了额外的延迟和复杂性。后续的 IMPALA 和 SEED RL 等工作针对大规模分布式训练进行了重新设计。

## 9. 历史意义

**第一，复兴了 Actor-Critic 方法家族。** 在 A3C 之前，深度 RL 的主流几乎被 DQN 及其变体（Double DQN、Dueling DQN、Prioritized Experience Replay 等）所垄断。Actor-Critic 方法虽然理论上有诸多优势（可处理连续动作空间、可结合策略梯度与价值估计等），但在深度学习中一直被认为不稳定。A3C 的成功彻底扭转了这一局面，开启了 Actor-Critic 方法在深度 RL 中的黄金时代。此后的 PPO、SAC、TD3、IMPALA 等几乎所有主流算法都属于 Actor-Critic 家族。

**第二，确立了异步/并行训练作为深度 RL 的标准范式。** A3C 之前，深度 RL 的训练基本是"单 GPU + 经验回放"的模式。A3C 证明了并行化不仅是一种加速手段，更是一种根本性的训练稳定化机制。这一洞察对后续的分布式 RL 研究（Gorila、IMPALA、SEED RL、R2D2）产生了深远影响，并行训练逐渐成为深度 RL 的默认配置。

**第三，降低了深度 RL 研究的门槛。** 通过证明 CPU 训练的可行性，A3C 使得没有高端 GPU 的研究者和学生也能进行深度 RL 的实验。这在民主化 AI 研究方面具有重要意义，直接促进了深度 RL 研究社区的扩大。

**第四，催生了大量后续工作。** A3C 的框架和思想直接启发了：PPO（通过信任域约束替代异步更新来稳定训练）、IMPALA（通过 V-trace 修正旧梯度问题）、A2C（A3C 的同步版本）、ACER（off-policy Actor-Critic with experience replay）、GAE（广义优势估计，系统化了 A3C 中的优势函数估计）、SAC（将 A3C 的熵正则化发展为完整的最大熵框架）等。可以毫不夸张地说，A3C 是过去十年中影响力最大的深度 RL 论文之一。

**第五，为强化学习的实际应用铺平了道路。** A3C 的低资源需求和快速训练特性使得 RL 在工业界的应用变得更加可行。推荐系统、游戏 AI、机器人控制等领域都从 A3C 及其后续工作中受益。

## 10. 今天的视角再看

从 2024-2025 年的视角回望 A3C，它的地位可以类比为深度 RL 中的"AlexNet"——不是最终的最优解，但是开启了正确方向的关键突破。

**PPO 的崛起与 A3C 的退场。** 在实际应用中，A3C 已经在很大程度上被 PPO（Proximal Policy Optimization, Schulman et al., 2017）所取代。PPO 保留了 A3C 的 Actor-Critic 架构和优势函数的使用，但用 clipped surrogate objective 替代了异步更新来控制策略更新幅度，实现了更稳定、更可复现的训练。PPO 成为了当今最广泛使用的深度 RL 算法，从 OpenAI Five 到 ChatGPT 的 RLHF 训练，都采用了 PPO 或其变体。

**IMPALA 与 V-trace 的修正。** DeepMind 在 2018 年提出的 IMPALA 直接继承了 A3C 的分布式训练理念，但通过 V-trace 修正目标解决了旧梯度带来的 off-policy 偏差问题，并将架构扩展到数千个 actor 的规模。IMPALA 可以被视为 A3C 的"工业级版本"。

**分布式训练成为标准。** A3C 开启的并行训练范式已经成为深度 RL 的标准实践。SEED RL（Scalable, Efficient Deep-RL, 2019）进一步优化了 actor-learner 架构的通信效率；Sample Factory（2020）在单机上实现了每秒数十万帧的训练吞吐量。今天，几乎没有研究团队还会在单个环境实例上串行训练 RL 智能体。

**从异步到同步的回摆。** 有趣的是，实践中 A3C 的同步版本 A2C 往往被更多使用。原因在于：（1）现代硬件的并行能力使得同步等待的开销变得微不足道；（2）同步更新保证了可复现性，这在研究中至关重要；（3）GPU 的批处理效率使得同步收集一批数据后再统一前向/反向传播比多线程异步更新更高效。这说明 A3C 的核心贡献不在于"异步"本身，而在于"并行化去相关"的思想。

**大规模 RL 的新挑战。** 在大规模语言模型的 RLHF（Reinforcement Learning from Human Feedback）训练中，A3C 的精神依然存在：多个 rollout worker 并行地与环境（人类评估者或奖励模型）交互，收集大量数据后更新策略模型。虽然具体的算法已经进化为 PPO 或 DPO，但"并行收集、批量更新"的框架理念直接源自 A3C。

**Actor-Critic 的持续演进。** A3C 复兴的 Actor-Critic 方法今天已经发展为一个庞大的算法家族。在连续控制领域，SAC（Soft Actor-Critic）将 A3C 的熵正则化思想发展为完整的最大熵框架，成为机器人学习的首选算法；TD3（Twin Delayed DDPG）通过双 critic 和延迟更新进一步稳定了训练。在离散动作空间中，R2D2 将 Actor-Critic 与 LSTM 和分布式训练结合，在 Atari 上达到了超人水平。

## 11. 通俗科普版解释

想象你是一家大型连锁餐厅的厨师长，需要开发一道新菜品。

**DQN 的方式**就像是：你一个人在厨房里反复尝试，每次试完后把配方和结果记录在一本大笔记本上（经验回放缓冲区）。过一段时间，你翻开笔记本，随机挑几条记录来复习和改进。这个方法有效，但你需要一本很大的笔记本（大量内存），而且只有你一个人在干活（单线程训练），进度很慢。

**A3C 的方式**则完全不同：你同时派出 16 个厨师（16 个线程），每人分到一间独立的厨房（独立的环境副本），各自独立实验。每个厨师做了几道菜之后，就跑到餐厅大厅的公告板上（共享参数），把自己的心得写上去，同时看看其他厨师最新的发现，然后回到厨房继续实验。

这里的关键洞察是：因为 16 个厨师在尝试完全不同的配方组合（不同的环境状态），他们贡献的经验自然是多样化的，不需要那本大笔记本就能避免"反复尝试同一种配方"的问题。而且，16 个人同时工作比 1 个人翻笔记本快得多。

每个厨师不仅要给菜品打分（critic: 这道菜能得几分？），还要决定下一步尝试什么配方（actor: 应该加什么调料？）。他们用"这个配方比平均水平好多少"（优势函数）来指导改进方向——如果加了某种调料后效果比平均好很多，就多往这个方向探索；如果效果比平均差，就少用这个配料。

为了防止所有厨师最终都收敛到同一道菜而错过可能更好的创意，还有一条规则：鼓励保持一定的创新（熵正则化）。不要太快确定最终方案，多尝试一些不寻常的组合。

最终的结果是：16 个厨师用一天时间开发出的菜品，比一个厨师用一周时间、一本大笔记本开发出的还要好。而且，你只需要一间普通的商用厨房（多核 CPU），不需要最顶级的专业设备（GPU）。

## 12. 可引用摘要

**摘要一（核心方法）**：
A3C（Asynchronous Advantage Actor-Critic）通过在多个并行线程中各自运行独立的 actor-learner，利用异步梯度更新替代经验回放来打破数据相关性，在单台多核 CPU 上即实现了超越 GPU 训练的 DQN 的性能，同时将训练时间从数天缩短到数小时。

**摘要二（历史地位）**：
Mnih et al. (2016) 的 A3C 论文复兴了 Actor-Critic 方法在深度强化学习中的应用，确立了异步并行训练作为深度 RL 的标准范式，直接催生了 PPO、IMPALA、SAC 等后续主流算法，是过去十年中引用量最高、影响力最大的深度 RL 论文之一。

**摘要三（技术贡献）**：
A3C 的核心技术贡献包括：（1）证明异步并行化可替代经验回放实现去相关化；（2）提出共享参数的 Actor-Critic 网络架构；（3）系统化引入熵正则化防止策略过早收敛；（4）展示 n-step return 在深度 RL 中的实际有效性；（5）将深度 RL 的适用范围从离散动作空间扩展到连续控制。

**摘要四（实践影响）**：
A3C 将深度 RL 训练的硬件门槛从昂贵的 GPU 降低到普通的多核 CPU，训练时间从数天缩短到数小时，使得深度 RL 研究不再是少数资源充足的实验室的专属领地，极大地推动了该领域的民主化和社区扩大。

**摘要五（当代视角）**：
虽然 A3C 在实践中已被 PPO 和 IMPALA 等后续算法取代，但其"并行化去相关"的核心思想已成为现代分布式 RL 训练的基本范式，从 OpenAI Five 到大语言模型的 RLHF 训练，A3C 开创的框架理念无处不在。
