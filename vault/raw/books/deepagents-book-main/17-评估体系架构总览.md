# 第 17 章：评估体系架构总览

**主要源码路径**

- `libs/evals/tests/evals/utils.py`
- `libs/evals/tests/evals/conftest.py`
- `libs/evals/deepagents_evals/categories.json`

本章说明 deepagents 项目在 `libs/evals/` 下的评估架构：如何用轨迹数据表示一次智能体运行，如何用「成功断言」与「效率断言」两层模型区分「对错」与「形态」，以及 pytest 与 LangSmith 如何接入。

---

## 1. 评估代码在仓库中的位置

可执行评估逻辑集中在 `libs/evals/`：测试与工具函数位于 `tests/evals/`，分类与雷达图等共享配置位于 `deepagents_evals/`。理解评估体系应优先阅读 `utils.py`（轨迹、断言、`run_agent`）与 `conftest.py`（环境门禁与 CLI）。

---

## 2. 两层断言模型

评估框架将断言分为两类，职责清晰分离。

### 2.1 成功断言（Success Assertions，`.success(...)`）

- **语义**：正确性检查；任一失败则 **硬性失败** 当前测试（`pytest.fail`）。
- **典型能力**：最终回复是否包含子串、文件内容是否等于预期、`LLMJudge` 是否全部准则通过等。
- **工厂函数示例**（定义于 `utils.py`）：`final_text_contains`、`file_equals` 等，均返回 `SuccessAssertion` 的子类实例。

### 2.2 效率断言（Efficiency Assertions，`.expect(...)`）

- **语义**：对轨迹「形状」的期望（步数、工具调用次数、特定工具调用是否出现等）。
- **行为**：通过 LangSmith `log_feedback` **记录**；**不会**导致测试失败（见 `_assert_expectations` 中对 `_success` 与 `_expectations` 的分支处理）。
- **实现基类**：`EfficiencyAssertion`；常见具体类包括 `AgentSteps`、`ToolCallRequests`、`ToolCall`。

**设计取舍**：把「必须做对」与「希望省步数 / 工具调用」拆开，避免模型因探索性多走一步就整例标红，同时仍能在报表与 LangSmith 中观察效率偏差。

## 3. 核心类型（`utils.py`）

### 3.1 `AgentStep`（`dataclass`）

- **字段**：`index`（从 1 起计）、`action`（`AIMessage`）、`observations`（`list[ToolMessage]`）。
- **含义**：智能体在一个「回合」内的决策及其后随的观测（工具返回）。

### 3.2 `AgentTrajectory`（`dataclass`）

- **字段**：`steps`、`files`（路径到文件内容的映射）。
- **`answer` 属性**：取最后一步 `AIMessage` 的文本，便于断言最终对外回复。
- **`pretty()`**：生成人类可读的轨迹摘要（每步的工具调用与文本预览），用于失败信息与 LLM 评判上下文。

### 3.3 `SuccessAssertion`

- 正确性断言的抽象基类：子类实现 `check(trajectory) -> bool` 与 `describe_failure(trajectory) -> str`。

### 3.4 `TrajectoryScorer`

- **不可变 dataclass**，采用 **建造者风格** 链式配置：
  - `.success(*SuccessAssertion)`：追加成功断言；
  - `.expect(...)`：通过关键字参数追加效率断言（如 `agent_steps=`、`tool_call_requests=`、`tool_calls=` 列表）。

内部以 `_success`、`_expectations` 两个元组分别保存两类断言。

## 4. 入口函数 `run_agent`

**源码**：`run_agent` 定义于 `utils.py`。

**职责**（调用方通常已用 `create_deep_agent` 等建好 `CompiledStateGraph`）：

1. 将 `query`（字符串或消息列表）与可选 `initial_files` 组装为 `invoke` 输入；
2. 生成或使用 `thread_id`，调用 `agent.invoke`；
3. 通过 LangSmith 记录规范化后的 `inputs` / `outputs`（避免测试夹具噪声污染数据集示例）；
4. 用 `_trajectory_from_result` 从 `result["messages"]` 与 `result["files"]` 构建 `AgentTrajectory`；
5. 若传入 `scorer`，则执行 `_assert_expectations`：先记录效率相关 feedback，再逐项运行成功断言。

**模块关系**：测试文件构造 agent 与 `TrajectoryScorer`，再调用 `run_agent`；`pytest_reporter` 通过回调收集 `EfficiencyResult` 用于会话级指标。

## 5. 评估分类与雷达维度（`categories.json`）

`categories.json` 中 `categories` 列出全部评估维度：

- `file_operations`
- `retrieval`
- `tool_use`
- `memory`
- `conversation`
- `summarization`
- `unit_test`

`radar_categories` 为雷达图所用 **子集**：与 `categories` 相比 **不包含** `unit_test`，避免将偏 SDK / 单元行为的用例与「模型能力」维度混在同一雷达上。

`labels` 提供各分类的短标签（如 UI 或图表轴标题）。

## 6. pytest 配置（`conftest.py`）

### 6.1 LangSmith 追踪门禁

`pytest_configure` 要求启用追踪：检查 `LANGSMITH_TRACING`、`LANGSMITH_TRACING_V2`、`LANGCHAIN_TRACING_V2`、`LANGCHAIN_TRACING` 等环境变量是否为 `"true"`。未启用则 **整个会话以退出码 1 中止**，并提示设置 API Key 与追踪开关。评估用例普遍配合 `@pytest.mark.langsmith` 使用。

### 6.2 插件与 CLI

- `pytest_plugins = ["tests.evals.pytest_reporter"]`：挂载会话级报告与 JSON 输出（详见第 18 章）。
- **`--model`**：指定被测模型；省略时使用 `deepagents.graph.get_default_model()` 的模型名。
- **`--eval-category`**：可重复；仅收集带对应 `eval_category` 标记的用例；未知分类名会报错退出。
- **`--openrouter-provider`**：固定 OpenRouter 提供方（需 `openrouter:` 前缀模型名）。

### 6.3 Fixture

- **`model_name`**：由 `pytest_generate_tests` 与 `--model` 参数化。
- **`model`**：基于 `model_name` 调用 `init_chat_model`；对 `openrouter:` 模型注入超时等 kwargs。
- **`langsmith_experiment_metadata`**：会话级元数据（模型、日期、deepagents 版本），供实验组织使用。

## 7. 示例：组合效率期望与成功断言

```python
scorer = (
    TrajectoryScorer()
    .expect(agent_steps=2, tool_call_requests=1)
    .success(final_text_contains("three", case_insensitive=True))
)
```

含义：期望 2 步、1 次工具调用请求（仅记录与指标，失败不红）；最终回复须包含 `"three"`（不区分大小写），否则测试失败。

## 8. 小结

| 组件 | 作用 |
|------|------|
| `AgentStep` / `AgentTrajectory` | 结构化表示一次运行的消息与文件终态 |
| `SuccessAssertion` / `EfficiencyAssertion` | 硬失败 vs 仅记录 |
| `TrajectoryScorer` | 统一挂载两类断言的不可变建造者 |
| `run_agent` | invoke、轨迹构建、断言与 LangSmith 记录 |
| `categories.json` | 分类全集与雷达子集 |
| `conftest.py` | 追踪门禁、模型与分类筛选 fixture |
