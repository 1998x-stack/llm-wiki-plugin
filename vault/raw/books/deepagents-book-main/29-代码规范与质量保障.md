# 代码规范与质量保障

## 文档来源与路径

| 类型 | 路径 |
|------|------|
| 全局开发指南 | `AGENTS.md`（仓库根目录） |
| 各包工具配置 | 各 `libs/*/pyproject.toml` 中的 `[tool.ruff]`、`[tool.ty]`、`[tool.pytest.ini_options]` 等 |

---

## 概述

`AGENTS.md` 定义 Deep Agents **Python monorepo** 的架构认知、工具链、提交与 PR 规范、**代码质量与安全红线**、**测试布局** 以及 **公共 API 稳定性** 要求。本文档提炼其要点，便于写书或 onboarding 时快速对齐。

---

## 提交与 PR 规范

### Conventional Commits

- PR 标题建议符合 **约定式提交**，类型与 scope 以 **`.github/workflows/pr_lint.yml`** 为准。
- 示例（`AGENTS.md`）：
  - `feat(sdk): add new chat completion feature`
  - `fix(cli): resolve type hinting issue`
  - `chore(evals): update infrastructure dependencies`
- **大小写**：除专有名词外，标题倾向 **小写**。

### AI 辅助贡献

- PR 描述中需 **声明 AI 如何参与**；说明变更动机（「为什么」）与 **需重点人工审查** 的区域。

## 工具链

| 工具 | 用途 |
|------|------|
| **uv** | 依赖与虚拟环境管理；各 `libs/` 包自有 `pyproject.toml` / `uv.lock`。 |
| **make** | 聚合常用命令（`make test`、`make lint`、`make format` 等，以根与各包 `Makefile` 为准）。 |
| **ruff** | **Lint + 格式化**（替代 flake8、black、isort 等分散工具）。 |
| **ty** | **静态类型检查**。 |
| **pytest** | **测试运行框架**。 |

### 抑制 ruff 规则

- **优先行内 `# noqa: RULE`**：精确到行，避免掩盖同文件其他问题。
- **`per-file-ignores`**：仅用于 **整类文件策略**（如 `tests/**` 不要求 docstring、允许 `assert`），不为单行例外滥用。

---

## 代码质量规则

- **公共 API**：**完整类型标注**与返回值类型。
- **文档字符串**：**Google 风格**（含 `Args` 等）；类型信息放在 **签名** 中，避免在 docstring 重复默认可从签名读出的默认值。
- **语言**：**美式英语**（如 behavior，非 behaviour）。
- **内联代码格式**：**禁止 Sphinx 双反引号** `` ``code`` ``；在 docstring/注释中使用 **单反引号** `` `code` ``。
- **API 演进**：新增参数宜为 **仅限关键字**（`*, new_param=...`），利于向后兼容。

---

## 安全约束

- **禁止**对用户可控输入使用 **`eval` / `exec` / `pickle`**。
- **不可信代码**须在 **沙箱边界** 内执行（与 `SandboxBackendProtocol`、合作伙伴沙箱包的设计一致）。
- 异常处理避免 **裸 `except:`**；错误信息宜使用明确变量（如 `msg`）。

---

## 测试布局

| 目录 | 约定 |
|------|------|
| `tests/unit_tests/` | **快速**、**禁止网络**依赖。 |
| `tests/integration_tests/` | 允许网络；可能需要 **API Key**。 |
| **async** | 包内 `pyproject.toml` 通常设 `asyncio_mode = "auto"`，**不要**在单个测试上冗余加 `@pytest.mark.asyncio`。 |
| **结构** | 测试目录 **镜像源码结构**，便于定位。 |
| **风格** | 少 mock，多测真实实现；避免把业务逻辑复制进测试。 |

---

## 公共接口稳定性

- 修改前检查符号是否在 **`__init__.py` 导出**。
- 搜索测试与示例中的用法；**任意签名变动**都应视为高风险并告知维护者。
- 实验能力用 docstring **显著标注**（如 MkDocs Material 的 `!!! warning` 类提示）。

---

## 本地开发：可编辑依赖

- monorepo 内常用 **`[tool.uv.sources]`** 指向 **path + editable**，使 SDK 与各集成包联调时无需反复安装 wheel。

---

## 设计取舍

- **ruff 一体化**：降低配置分散与格式化/检查不一致问题。
- **测试目录约定**：从路径即可判断能否离线跑，便于 CI 分层。
- **keyword-only 新参数**：在快速迭代期仍尽量保护下游调用方。

---

## 小结

质量保障由 **`AGENTS.md` 规范 + ruff/ty/pytest 工具链 + 测试目录约定 + 安全清单** 共同构成；贡献前应先读 `AGENTS.md` 全文，再对照目标包的 `pyproject.toml` 微调。
