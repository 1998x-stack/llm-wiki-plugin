## 1. 本书视角：何谓「Harness 工程」

Deep Agents 在官方定位中是 **batteries-included agent harness**（开箱即用的智能体「马具」/ harness）：不强迫使用者从零拼装提示词、工具与上下文管理，而是通过 **可组合的默认能力** 快速得到可运行的智能体，再按需裁剪与扩展。  
从工程上看，本仓库是一个 **Python 单体仓库（monorepo）**，内含多个 **独立版本、独立锁文件** 的发布包；根目录不设统一的 `uv` workspace，也没有根级 `setup.py`，每个包自成一体，由 `make` 与 `libs/Makefile` 聚合常见开发任务。

## 2. 目录树总览

下列树形结构概括仓库顶层布局（注释为角色说明；与 `AGENTS.md` 中的 monorepo 描述一致并略作扩展）：

```
deepagents/
├── .github/           # CI/CD、脚本、Issue/PR 模板、文档用图片等
├── examples/          # 示例工程（各自 pyproject + uv.lock）
├── libs/
│   ├── deepagents/    # 核心 SDK
│   ├── cli/           # 终端 CLI / TUI
│   ├── acp/           # Agent Client Protocol 集成
│   ├── evals/         # 评测套件与 Harbor 等集成
│   ├── repl/          # REPL 中间件（langchain-repl）
│   └── partners/      # 合作方沙箱/运行时集成（多子包）
├── AGENTS.md          # 贡献者与 AI 辅助开发指南
├── README.md          # 项目对外说明与快速开始
└── release-please-config.json  # 发布与版本自动化配置
```

## 3. Monorepo 各包职责

### 3.1 `libs/deepagents/` — 核心 SDK

- **角色**：Deep Agents 的 **主库**，对外通常通过 PyPI 包名 `deepagents` 安装。  
- **能力概览**：提供工厂函数 `create_deep_agent`、多层 **middleware**、**BackendProtocol** 及多种存储/执行后端实现等。  
- **与全书关系**：第 2 章架构与「Harness」模式均以此包为中心展开。

### 3.2 `libs/cli/` — CLI / TUI

- **角色**：基于 [Textual](https://textual.textualize.io/) 的 **终端交互界面**，提供类似「编码助手」的终端体验。  
- **入口**：可执行名通常为 `deepagents` / `deepagents-cli`（以各包 `pyproject.toml` 中 `[project.scripts]` 为准）。  
- **设计要点**（见 `AGENTS.md`）：启动路径需 **延迟导入** 重型依赖（如 LangChain/LangGraph），避免 `-v` 等轻量命令也背负秒级启动成本；CLI 对 SDK 版本常有 **精确 pin**，与 CI 校验联动。

### 3.3 `libs/acp/` — Agent Client Protocol

- **角色**：**Agent Client Protocol（ACP）** 与 Deep Agents 的集成包（PyPI 名如 `deepagents-acp`），用于与遵循 ACP 的客户端/生态对接。  
- **注意**：仓库根目录 `AGENTS.md` 中曾用「Agent Context Protocol」表述，与 `libs/acp/pyproject.toml` 中的 **Agent Client Protocol** 以发布元数据为准。

### 3.4 `libs/evals/` — 评测

- **角色**：**评测套件**，含与 **Harbor** 等基础设施的集成及基准场景。  
- **维护提示**：`AGENTS.md` 说明 `evals` 下部分数据目录为上游 vendored，需保持字节级一致，且受 `.pre-commit-config.yaml` 中针对性排除项保护。

### 3.5 `libs/repl/` — REPL 中间件

- **角色**：包名 **`langchain-repl`**，描述为面向 deepagents 的 LangChain REPL；依赖核心 `deepagents`，用于 **交互式 REPL 场景** 的中间件能力（与 SDK、CLI 形成不同入口形态）。

### 3.6 `libs/partners/` — 合作方沙箱集成

- **角色**：**合作伙伴运行时/沙箱** 的独立集成包，按子目录拆分，例如：

  - `daytona/`  
  - `modal/`  
  - `quickjs/`  
  - `runloop/`  

  各子包自有 `Makefile`、`pyproject.toml`，便于单独发版与依赖隔离。

### 3.7 `examples/` — 示例工程

示例目录 **各自独立** 管理依赖（`pyproject.toml` + `uv.lock`），便于读者按需拷贝或参考。官方 `examples/README.md` 表格中重点介绍的部分包括：

| 目录 | 侧重点（简述） |
|------|----------------|
| `deep_research/` | 多步检索、子智能体、反思等研究型模式 |
| `content-builder-agent/` | 记忆（如 `AGENTS.md`）、skills、子智能体与内容生成 |
| `text-to-sql-agent/` | 自然语言转 SQL、技能工作流（本仓库另有此示例，可与书中「典型应用」对照） |
| `ralph_mode/` | 循环自治模式，借助文件系统持久化上下文 |
| `downloading_agents/` | 「智能体即文件夹」——下载、解压、运行 |

此外，仓库中还可找到如 **`async-subagent-server/`**（异步子智能体服务端模式）、**`nvidia_deep_agent/`**（GPU/领域技能示例）等，均属于 **同一 `examples/` 生态下的变体**，适合作为 harness 扩展与垂直场景参考。

### 3.8 `.github/`

- **CI 工作流**：各包 lint、测试、发布相关 workflow。  
- **脚本与模板**：PR/Issue 模板、发布说明脚本等。  
- **静态资源**：如 `README.md` 引用的 logo 等图片。

## 4. 构建与开发工具链

与 `AGENTS.md`、`README.md` 及 `libs/Makefile` 一致，日常开发依赖如下：

| 工具 | 用途 |
|------|------|
| **uv** | 包管理与锁文件解析；替代传统 pip/poetry 工作流，各包目录下独立 `uv lock` |
| **make** | 通过 **`libs/Makefile`** 聚合 `lint`、`format`、`lock`、`lock-check` 等，并向下调用各 `libs/*/Makefile` |
| **ruff** | 快速 lint 与 format；项目倾向 **行内 `# noqa`** 处理个别例外，`per-file-ignores` 仅用于测试等 **类别策略** |
| **ty** | 静态类型检查 |
| **pytest** | 单元测试与集成测试；`make test` 或 `uv run --group test pytest ...`（以各包配置为准） |

**Python 版本提示**：`libs/Makefile` 中为 **`acp` 包使用 Python 3.14**，其余参与聚合的包默认按 **3.12** 解析锁文件，这在多包 CI 与本地 `uv lock` 时需注意。

## 5. 关键配置文件

| 文件 | 作用 |
|------|------|
| **`libs/*/pyproject.toml`** | 各包元数据、依赖、工具配置（ruff、pytest、uv sources 等） |
| **`libs/*/uv.lock`** | 各包 **独立** 的依赖锁定，保证可复现安装 |
| **`release-please-config.json`**（根目录） | 与 Release Please 流程配合的版本与 changelog 自动化（详见 `.github/RELEASING.md` 等文档） |
| **`.pre-commit-config.yaml`** | 提交前钩子（格式化、换行、部分路径排除等） |
| **`.mcp.json`** | MCP 相关配置；`AGENTS.md` 建议需要时可配合文档类 MCP 使用 |

**刻意未采用的模式**：

- 根目录 **无** `setup.py`、**无** 单一「全仓库一体」的 uv workspace。  
- 每个库包 **独立发版、独立锁文件**，依赖关系通过 PyPI 或 `[tool.uv.sources]` 的 **可编辑本地路径** 在开发时桥接。

## 6. 如何从文档回到代码

1. **产品叙事与快速上手**：读根目录 `README.md`（安装、`create_deep_agent` 最小示例、CLI 简介、LangGraph 原生性说明）。  
2. **贡献与内部约定**：读 `AGENTS.md`（monorepo 结构、命令、测试规范、CLI/Textual 专项、evals 数据约束、PR 约定）。  
3. **改某一包**：进入对应 `libs/<name>/`，阅读该包 `pyproject.toml` 与 `Makefile`，再下钻源码。

下一章将基于 **`libs/deepagents/deepagents/graph.py`** 等模块，从 **Harness 三层架构**（后端 / 中间件 / 图编排）展开设计哲学与默认中间件栈顺序。
