# 合作伙伴沙箱集成（libs/partners）

## 文档来源与路径

| 类型 | 路径 |
|------|------|
| 合作伙伴根目录 | `libs/partners/` |
| Daytona | `libs/partners/daytona/` |
| Modal | `libs/partners/modal/` |
| QuickJS | `libs/partners/quickjs/` |
| Runloop | `libs/partners/runloop/` |
| CLI 统一工厂（选型入口） | `libs/cli/deepagents_cli/integrations/sandbox_factory.py` |
| 协议定义（SDK） | `libs/deepagents/deepagents/backends/protocol.py`（`SandboxBackendProtocol`） |

---

## 概述

`libs/partners/` 下的多个 **独立 Python 包** 为 Deep Agents 提供 **远程或可隔离的执行后端**：多数实现为 **Sandbox**，与 SDK 中的 `SandboxBackendProtocol` 对齐，从而在文件系统中间件等位置挂载 **`execute` 工具**（仅当后端支持该协议时）。

**CLI 侧**：`deepagents_cli.integrations.sandbox_factory.create_sandbox()` 按 **provider 名称** 解析并创建/连接对应后端（如 `daytona`、`modal`、`runloop` 等），与 **SDK 直接传入 backend 实例** 两种方式并存。

---

## 协议与统一抽象

- **`SandboxBackendProtocol`**（定义于 Deep Agents SDK 的 backends 协议模块）：合作伙伴提供的 Sandbox 类 **应实现该协议**，以便与 `CompositeBackend`、文件系统中间件、`execute` 工具逻辑一致协作。
- **工厂函数** `create_sandbox(provider, ...)`：返回 `Generator[SandboxBackendProtocol, None, None]`，内部通过 `sandbox_provider` 等模块完成各厂商 SDK 的适配与生命周期管理。

## 四个合作伙伴一览

### 1. Daytona（`libs/partners/daytona/`）

| 项 | 内容 |
|----|------|
| 包名 | `langchain-daytona` |
| 主要导出 | `DaytonaSandbox`（`langchain_daytona`） |
| 定位 | **云端开发沙箱**，适合在隔离环境中跑命令与项目 |
| 凭证 | 通常需要 **`DAYTONA_API_KEY`**（以各包 README / 厂商文档为准） |

### 2. Modal（`libs/partners/modal/`）

| 项 | 内容 |
|----|------|
| 包名 | `langchain-modal` |
| 主要导出 | `ModalSandbox` |
| 定位 | **Serverless 云算力**，适合弹性、可扩展执行；**支持 GPU**，便于重计算场景 |
| 依赖 | `modal` Python SDK（见 `pyproject.toml`） |

### 3. QuickJS（`libs/partners/quickjs/`）

| 项 | 内容 |
|----|------|
| 包名 | `langchain-quickjs` |
| 主要导出 | **`QuickJSMiddleware`**（**中间件**，不是 Sandbox 类） |
| 定位 | **轻量 JavaScript 执行**（嵌入式 QuickJS） |
| 模式说明 | 与 Daytona/Modal/Runloop 的 **SandboxBackendProtocol** 路径不同：以 **Middleware** 注入 JS 执行能力，集成点偏向中间件链而非统一 `execute` 沙箱后端 |

### 4. Runloop（`libs/partners/runloop/`）

| 项 | 内容 |
|----|------|
| 包名 | `langchain-runloop` |
| 主要导出 | `RunloopSandbox` |
| 定位 | **托管沙箱环境**（Runloop 平台） |
| 依赖 | `runloop-api-client` |

## 各包工程结构（共同模式）

每个合作伙伴目录通常包含：

- 独立的 **`pyproject.toml`** 与 **`uv.lock`**
- 源码子包（如 `langchain_daytona/`、`langchain_modal/` 等）
- 各自的 **`tests/`** 目录

便于 **独立发版、独立 CI 矩阵项**（与主仓库 `.github/workflows/ci.yml` 中按路径检测的 `daytona`、`modal`、`runloop`、`quickjs` 等 filter 输出一致）。

---

## 选型与集成路径

1. **CLI**：用户选择 sandbox provider 时，由 `sandbox_factory.create_sandbox` 统一创建；默认工作目录等映射在工厂模块的 `_PROVIDER_TO_WORKING_DIR` 等常量中维护（如 `daytona` → `/home/daytona`，`modal` → `/workspace` 等）。
2. **SDK / 应用代码**：可直接构造 `DaytonaSandbox`、`ModalSandbox`、`RunloopSandbox` 等，作为 `create_deep_agent(..., backend=...)` 或复合后端的一部分传入。
3. **QuickJS**：在需要 **JS 片段执行** 且不希望走完整远程沙箱时，优先考虑 **`QuickJSMiddleware`**。

---

## 设计取舍

- **协议一致、实现分散**：Sandbox 实现放在 `libs/partners/*`，避免核心 SDK 直接依赖所有云厂商；需要时再安装对应可选依赖。
- **QuickJS 例外导出 Middleware**：JS 执行体量与集成方式与「远程 Linux 沙箱」不同，故采用中间件模式更贴切。
- **CLI 工厂集中化**：降低主程序对各 `import langchain_*` 细节的重复代码，统一生命周期（创建、复用 `sandbox_id`、setup 脚本等）。

---

## 小结

`libs/partners/` 提供 **Daytona / Modal / Runloop** 三类 **SandboxBackendProtocol** 实现及 **QuickJS** 的 **Middleware** 路线；与 Deep Agents 核心通过 **协议 + CLI 工厂** 连接，可按场景选择云端沙箱或轻量 JS 执行。
