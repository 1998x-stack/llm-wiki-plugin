## 概述

Deep Agents **evals** 在 **真实 LLM** 下端到端运行智能体，并对 **轨迹**（步骤数、工具调用、最终文本、文件状态等）断言。框架以 **LangSmith** 记录运行；本地/CI 需配置 tracing 与 API Key（详见 `libs/evals/README.md`）。

**两层断言模型**：

- **`.success(...)`**：**必须通过**的正确性断言（硬失败）。
- **`.expect(...)`**：**效率或形状期望**（软指标，**记录但不导致测试失败**）。

---

## 新建评估用例：五步流程

1. 使用 **`@pytest.mark.langsmith`** 标记测试函数（与 `langsmith.testing` 集成，用于日志与报告）。
2. 通过 fixture 注入 **`model: BaseChatModel`**。
3. 使用 **`create_deep_agent(model=model, ...)`** 构造智能体（可按场景附加 tools、middleware、backend 等）。
4. 调用 **`run_agent(agent, model=model, query=..., scorer=...)`** 执行一次评估回合。
5. 在 `TrajectoryScorer` 链上组合 **`.success(...)`** 与 **`.expect(...)`**。

### 示例代码

```python
@pytest.mark.langsmith
def test_example(model: BaseChatModel) -> None:
    agent = create_deep_agent(model=model)
    run_agent(
        agent,
        model=model,
        query="What is 2 + 2?",
        scorer=(
            TrajectoryScorer()
            .expect(agent_steps=1)
            .success(final_text_contains("4"))
        ),
    )
```

语义判分可结合 `tests/evals/llm_judge.py` 中的 **`llm_judge`** 等（当子串匹配不足时）。

## 新增评估分类

1. 编辑 **`deepagents_evals/categories.json`**：增加分类（若涉及雷达图能力维度，同时维护 **`radar_categories`** 等相关字段）。
2. 在对应测试上标注 **`@pytest.mark.eval_category("name")`**。
3. 在 **`tests/unit_tests/test_category_tagging.py`** 的 **`EXPECTED_CATEGORY_MODULES`** 中登记：该分类应对应哪些 eval 模块文件，防止磁盘上测试与声明脱节。
4. 运行 **`make test`**（或包内等价命令），让 **分类漂移检测** 与单元测试捕获遗漏。

---

## 评估目录（Eval catalog）

- **`EVAL_CATALOG.md`**：通过 **`make eval-catalog`** **自动生成**，按分类列出各 eval 及链接/路径。
- **漂移防护**：**`tests/unit_tests/test_eval_catalog.py`** 在 CI 中若发现目录 **与生成结果不一致** 则 **失败**，强制贡献者更新目录。

---

## 运行评估

- 在 `libs/evals/` 下：`make evals` 或按 README 使用 `uv run --group test pytest tests/evals ...`。
- **过滤**：
  - **`--eval-category`**：按分类筛选（可多次传入）。
  - **`--model`**：指定模型（与 `conftest.py` 中 CLI 选项一致）。


---

## 设计取舍

- **成功 vs 期望分离**：避免把「步数略多」这类软指标与正确性混为一谈，报告仍可看效率比率。
- **分类单源**：`categories.json` 服务雷达、聚合脚本与测试，减少三处各写一份的漂移。
- **目录生成 + 测试锁死**：让文档型 `EVAL_CATALOG.md` 不会悄悄过期。

---

## 小结

新 eval 遵循 **langsmith 标记 → model fixture → create_deep_agent → run_agent → Scorer** 固定套路；新分类要改 **JSON + marker + EXPECTED_CATEGORY_MODULES**；**`make eval-catalog`** 维护 **`EVAL_CATALOG.md`**，并由 **`test_eval_catalog.py`** 守门。
