# 什么是困惑度（Perplexity）？它如何评估语言模型性能？

> Source: 注意力掩码解析
> Time: 4/16/2026, 12:56:41 AM

## Question

什么是困惑度（Perplexity）？它如何评估语言模型性能？

## Answer

困惑度（Perplexity, PPL）是语言模型最经典的评估指标之一，用来衡量：


模型对一段文本“有多不困惑”，也就是它给真实下一个 token 分配的概率有多高。


一句话理解：


困惑度越低，说明模型越擅长预测文本

困惑度越高，说明模型越不确定、预测越差



1. 直观理解


语言模型的任务本质上是：


给定前文  $x_1, x_2, \dots, x_{t-1}$ ，预测下一个 token  $x_t$  的概率。


如果模型面对一句真实文本时，总能把正确下一个词的概率打得很高，说明它“懂这句话”。


如果它总是拿不准，给正确词的概率很低，就说明它“很困惑”。


所以 Perplexity 本质上是在衡量：


模型看到真实数据时的平均不确定性。



2. 数学定义


对于长度为  $N$  的序列  $x_1, x_2, \dots, x_N$ ，语言模型给出的概率是：


$$
P(x_1, x_2, \dots, x_N) = \prod_{t=1}^{N} P(x_t \mid x_{<t})
$$


困惑度定义为：


$$
\text{PPL} = P(x_1, x_2, \dots, x_N)^{-1/N}
$$


也常写成和交叉熵等价的形式：


$$
\text{PPL} = \exp\left(-\frac{1}{N}\sum_{t=1}^{N}\log P(x_t \mid x_{<t})\right)
$$



3. 它和交叉熵的关系


Perplexity 本质上就是平均负对数似然（NLL）或交叉熵取指数之后的结果。


如果平均 loss 是：


$$
L = -\frac{1}{N}\sum_{t=1}^{N}\log P(x_t \mid x_{<t})
$$


那么：


$$
\text{PPL} = e^L
$$


所以：


交叉熵越低，PPL 越低

PPL 越低，说明模型越好


这也是为什么训练语言模型时通常优化 cross-entropy loss，但评估时常汇报 perplexity。



4. 为什么叫“困惑度”


因为它可以理解成：


模型在每一步平均相当于要在多少个候选词里“猜一个”。


例如：


如果 PPL = 2，说明模型平均像是在 2 个候选里选，比较确定

如果 PPL = 100，说明模型平均像是在 100 个候选里选，很不确定


当然这只是直觉解释，不是严格字面含义，但很好理解。



5. 一个简单例子


假设测试集有 3 个 token，模型对真实 token 给出的条件概率分别是：


0.8

0.5

0.25


那么平均负对数似然是：


$$
L = -\frac{1}{3}(\log 0.8 + \log 0.5 + \log 0.25)
$$


困惑度就是：


$$
\text{PPL} = \exp(L)
$$


因为第三个 token 概率很低，所以 PPL 会被拉高，表示模型在这段文本上更“困惑”。



6. 它如何评估语言模型性能


Perplexity 的使用方式通常是：


1）准备测试集


用一批模型没见过的文本作为验证集或测试集。


2）让模型逐 token 计算真实文本概率


对每个位置，输入前文，让模型预测真实下一个 token 的概率。


3）求平均负对数似然，再取指数


得到整体 perplexity。


4）比较不同模型


在同一数据集、同一 tokenization、同一评估设置下：


PPL 更低的模型，通常语言建模能力更强



7. PPL 能说明什么


能说明的


PPL 低，通常表示模型：


对语言分布拟合更好

预测下一个 token 更准

在纯语言建模任务上更强


对于 base LM，这通常是一个很重要的自动评估指标。



8. PPL 不能完全说明什么


这是面试里很关键的一点。


1）PPL 低，不一定回答更有用


一个模型可能很会预测自然语言，但不一定：


更符合人类偏好

更会对话

更安全

更会遵循指令


所以在 ChatGPT 这类模型中，光看 PPL 不够。



2）PPL 不一定反映生成质量的全部


例如：


文本是否有逻辑

是否有事实错误

是否啰嗦

是否符合任务要求


这些都不是 PPL 单独能完整衡量的。



3）不同模型之间不能随便直接比 PPL


因为 PPL 很依赖：


数据集是否相同

tokenization 是否相同

词表大小是否相同

评估方式是否相同


比如两个模型 tokenizer 不一样，即使在同一语料上，PPL 也可能不能直接公平比较。



9. PPL 的优点


1）定义清晰，计算方便


它直接来自概率模型本身，和训练目标一致。


2）适合评估 base language model


特别是纯 next-token prediction 模型。


3）可用于训练过程监控


训练中常看：


train perplexity

validation perplexity


来判断模型是否收敛、是否过拟合。



10. PPL 的局限


1）只关注“真实 token 概率”


它衡量的是模型给标准答案的概率高不高，不直接衡量生成文本是否“好读”“有帮助”。


2）和人类偏好不完全一致


特别是在 instruction tuning、RLHF 之后，模型优化目标已经不只是语言建模概率。


3）对开放式生成评估有限


同一个 prompt 可以有很多合理答案，但 PPL 只看参考文本那一条路径。



11. 在不同模型里的意义


对传统语言模型 / Base LM


PPL 很重要，是核心指标之一。


对指令微调模型 / 对话模型


PPL 仍然有参考价值，但通常不再是最终目标。
还需要结合：


人工评测

win rate

task accuracy

factuality

harmlessness / helpfulness


因为用户真正关心的是“回答是否好用”，而不仅是“是否更像训练语料”。



12. 一个很常见的面试表达


可以这样说：


Perplexity 是语言模型对测试文本平均不确定性的度量，本质上是平均负对数似然的指数形式。它反映模型给真实下一个 token 分配概率的能力，数值越低表示模型越擅长建模语言分布。Perplexity 常用于评估和比较 base language model 的性能，但它不能完全代表生成文本的质量，也不能充分衡量指令跟随、人类偏好对齐和事实正确性。



13. 最后做个简洁总结


定义


Perplexity 衡量模型对真实文本的预测难度。


数学本质


它是平均交叉熵的指数。


如何看


越低越好

表示模型越不“困惑”


适合评估什么


语言建模能力

next-token prediction 能力


不足


不能全面代表对话质量、任务完成度和人类偏好
