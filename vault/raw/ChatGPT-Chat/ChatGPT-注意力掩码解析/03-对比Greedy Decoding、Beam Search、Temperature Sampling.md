# 对比Greedy Decoding、Beam Search、Temperature Sampling、Top-p Sampling的优缺点

> Source: 注意力掩码解析
> Time: 4/16/2026, 12:46:21 AM

## Question

对比Greedy Decoding、Beam Search、Temperature Sampling、Top-p Sampling的优缺点

## Answer

这四种解码方法的核心区别在于：


它们如何从模型给出的下一个 token 概率分布中，选出最终要生成的 token。


可以先用一句话概括：


Greedy Decoding：每一步都选概率最大的

Beam Search：保留多个高分候选路径，最后选整体分数最高的序列

Temperature Sampling：先调节分布“尖锐/平滑”程度，再按概率随机采样

Top-p Sampling：只在累计概率达到阈值  $p$  的候选集合中随机采样



1. Greedy Decoding


原理


每一步都直接选择当前概率最高的 token：


$$
x_t = \arg\max P(x_t \mid x_{<t})
$$


也就是“局部最优直接拿走”。



优点


1）简单


实现最直接，不需要维护多个候选。


2）速度快


每一步只选一个最大概率 token，推理开销最小。


3）结果稳定


同样输入基本总是得到相同输出，适合需要确定性的任务。



缺点


1）容易陷入局部最优


它只看当前这一步最优，不保证整句最优。


比如：


第一步选了当前最可能的词

但这个选择可能让后续整体表达变差


2）输出容易单调、重复


尤其在开放式生成里，经常出现：


语言保守

表达模板化

创造性差


3）不适合开放生成


比如写故事、聊天、创意写作，greedy 往往太“死板”。



适用场景


适合：


结构化输出

确定性较强的任务

对速度和稳定性要求高的场景


例如：


某些分类式生成

简短问答

受约束的代码补全



2. Beam Search


原理


Greedy 每一步只保留一个候选；
Beam Search 每一步保留  $k$  个得分最高的候选序列（beam width =  $k$ ）。


流程大致是：


第一步选出 top-k 个候选 token

第二步对每个候选再扩展出多个新候选

从所有扩展结果里保留总分最高的 k 条路径

重复直到结束


它优化的是整个序列的累计概率，而不是单步贪心。



优点


1）比 Greedy 更可能找到全局更优序列


因为它不是只押一个路径，而是保留多个备选。


2）生成质量通常更高


在机器翻译、摘要等任务里，beam search 往往比 greedy 更稳。


3）适合目标明确的生成任务


当“正确答案相对集中”时，beam search 表现较好。



缺点


1）计算更慢


每一步要维护多个候选，开销大于 greedy。


2）容易缺乏多样性


虽然保留多个候选，但它们往往都集中在高概率区域，最后结果还是比较保守。


3）可能偏向高频、安全、常见表达


因为它本质上在追求高概率序列，容易生成“看起来最稳妥”的句子。


4）长文本开放生成中不一定效果好


在对话、故事、创意写作中，beam search 经常会：


太公式化

太啰嗦

缺少自然随机性



适用场景


适合：


机器翻译

文本摘要

目标比较明确的 seq2seq 任务


不太适合：


聊天

小说生成

高创造性文本生成



3. Temperature Sampling


原理


在采样前，先用温度  $T$  调整 logits：


$$
P_i = \text{softmax}(z_i / T)
$$


其中：


$T < 1$ ：分布更尖锐，头部 token 概率更高

$T = 1$ ：原始分布

$T > 1$ ：分布更平滑，低概率 token 更容易被采到


然后再按这个新分布进行随机采样。



直觉理解


温度像一个“随机性旋钮”：


低温：更保守，更接近 greedy

高温：更发散，更有创造性，也更容易出错



优点


1）能增加多样性


不像 greedy 总选最大值，它允许从概率分布中随机抽样。


2）可控性强


通过调节 temperature，可以控制生成风格：


低温：稳

高温：活


3）适合开放式生成


在聊天、创意写作中，比 beam search 更自然。



缺点


1）温度太高时容易胡说


分布变平后，低概率 token 更容易被采样，可能导致：


语义跳跃

逻辑混乱

幻觉增加


2）温度太低时又退化成保守输出


接近 greedy，失去采样意义。


3）仅调温度不一定足够


如果尾部 token 特别多，仅靠 temperature 可能还是会采到很差的词。



适用场景


适合：


对话

创意写作

文案生成

希望输出有变化的任务



4. Top-p Sampling


原理


Top-p 也叫 Nucleus Sampling。


它不是固定保留前 k 个 token，而是：


从高到低排序后，取累计概率刚好超过  $p$  的最小 token 集合，再在这个集合里随机采样。


例如某一步 token 概率排序后：


A: 0.50

B: 0.25

C: 0.15

D: 0.06

E: 0.02

F: 0.01

...


如果设  $p = 0.9$ ，那么可能只保留：


A + B + C = 0.90


然后只在 {A, B, C} 里采样。



优点


1）比纯 temperature sampling 更稳


它会直接砍掉长尾低概率 token，减少离谱输出。


2）自适应


不同位置分布不同，候选集大小也自动变化：


分布很集中时，候选集很小

分布较平时，候选集会适当扩大


这比固定 top-k 更灵活。


3）兼顾质量和多样性


这是它最常被使用的原因。
既保留随机性，又避免过多尾部噪声。



缺点


1）仍然有随机性，不够确定


同样输入可能生成不同结果。


2）参数设置不当会影响效果


$p$  太小：太保守

$p$  太大：又可能引入太多噪声


3）在必须精确的任务上未必合适


比如某些严格推理、固定格式输出，随机采样可能带来不稳定。



适用场景


非常适合：


大模型对话

通用文本生成

创意任务

希望“自然且不过分发散”的场景


它是现在很多 LLM 默认或常用的解码思路之一。



5. 四者对比


5.1 输出风格对比


Greedy


最确定

最保守

最容易模板化


Beam Search


更关注整体高概率

质量通常比 greedy 高

但仍偏保守


Temperature Sampling


可调随机性

更灵活

高温时风险更大


Top-p Sampling


保留随机性

又比纯采样更稳

通常更适合 LLM 开放生成



5.2 速度对比


通常大致是：


Greedy 最快
Sampling 类（Temperature / Top-p）通常也较快
Beam Search 最慢


因为 beam 要同时维护多条路径。



5.3 确定性对比


从高到低大致是：


Greedy > Beam Search > Top-p / Temperature Sampling


其中采样方法天然更随机。



5.4 多样性对比


从低到高大致是：


Greedy < Beam Search < Top-p / Temperature Sampling


不过：


Temperature 太高会“乱”

Top-p 往往是在多样性和稳定性之间更平衡



6. 为什么大模型对话更常用 Top-p / Temperature，而不是 Beam Search


这是一个很常见的面试点。


原因是：


对话和开放文本生成不只是要“高概率”，还要“自然、多样、像人在说话”。


Beam Search 虽然追求高概率序列，但在开放式生成中容易导致：


输出机械

句子套路化

缺乏惊喜

重复和冗长


而 Top-p / Temperature Sampling：


能保留一定随机性

更接近日然语言生成的丰富性

更适合聊天、创作、头脑风暴


所以现代大模型生成通常更偏向：


temperature + top-p
而不是纯 beam search。



7. 一个直观例子


假设模型下一步概率分布是：


“非常” 0.40

“很” 0.30

“挺” 0.15

“有点” 0.08

“极其” 0.04

其他 0.03


如果要接在“这个方法___有效”后面：


Greedy


一定选“非常”


Beam Search


可能会探索：


“非常有效”

“很有效”

“挺有效”
最后选整句分数最高的那条


Temperature Sampling


可能选“非常”，也可能选“很”或“挺”，温度越高，选“有点”“极其”的概率越大


Top-p Sampling


如果  $p=0.85$ ，可能只保留：


非常 0.40

很 0.30

挺 0.15
累计正好 0.85


然后只在这三个里采样，不让“极其”这种更长尾的词进入候选。



8. 面试版总结


可以这样简洁回答：


Greedy Decoding 每步选择概率最大的 token，速度快、结果稳定，但容易陷入局部最优，输出缺乏多样性。Beam Search 同时保留多个高分候选路径，能够从序列级别寻找更优结果，适合翻译和摘要等任务，但计算更慢，且在开放生成中往往过于保守。Temperature Sampling 通过温度参数调节概率分布的平滑程度，再进行随机采样，能够控制生成的随机性和创造性，但温度过高时容易产生不稳定输出。Top-p Sampling 则只在累计概率达到阈值的候选集合内采样，能有效截断长尾噪声，通常比单纯的 temperature sampling 更稳，因此在大语言模型对话生成中非常常用。
