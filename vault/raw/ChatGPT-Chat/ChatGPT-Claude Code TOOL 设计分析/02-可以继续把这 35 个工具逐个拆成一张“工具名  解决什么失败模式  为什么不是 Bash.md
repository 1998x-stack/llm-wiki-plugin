TaskOutput
早期需要一个专门入口看后台任务输出。
它本来就在把“后台任务输出”做成会话一等公民，而不是 shell 抓日志。
纯 inspection，不是独立推理。
TodoWrite
早期模型容易忘任务，需要 checklist 保持方向。
Bash 写 TODO 文本不能保证 Claude 真把它当控制面。
它原本就是主会话的约束器，不是子代理。
Agent
主上下文装不下、任务可拆、需要并行或隔离时，得显式开一个子代理。
Bash 只能执行，不会给你一个新的 context window。
它本身就是“生成子代理”的原语。
SendMessage
子代理/队友开出来后，还得能继续协调、恢复、追加指令。
Bash 不具备 agent identity、resume、message routing 语义。
它就是围绕子代理的 orchestration primitive。
TeamCreate
单个子代理不够时，需要显式创建多 teammate 团队。
Bash 可以起多个进程，但不是 agent team abstraction。
这是“创建一组子代理”的工具，不是替代它们。
TeamDelete
团队存在就必须可回收、可清理。
Bash 杀进程不等于正确清理 teammate lifecycle。
它负责拆团队，不是再加一个团队成员。

这组里有三条特别重要：


第一，官方已经把 TaskOutput 标成 Deprecated，并明确建议改用 Read 去读后台任务输出文件；这说明 Anthropic 并不执着于“工具越来越多”，反而会收缩。Claude+2Claude+2


第二，TodoWrite 在官方博客里的定位已经很清楚：最初为了让模型不跑偏，但模型能力提升后，todo list 反而让 Claude 过度黏住旧计划；于是他们用 Task 取代它，因为 task 更适合 agents 之间通信、依赖关系和更新传播。与此同时，官方 tools reference 也写明了：TodoWrite 主要面向 non-interactive mode / Agent SDK，交互会话默认用 TaskCreate / TaskGet / TaskList / TaskUpdate。Claude+2Claude+2


第三，SendMessage、TeamCreate、TeamDelete 都不是默认普遍存在，而是只在设置了 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 时可用。这再次说明 Anthropic 对“多代理控制面”非常谨慎。Claude+1


工作区隔离



这一组很少，但非常“系统级”。它解决的不是思考问题，而是 让改动在文件系统 / Git 层面隔离。Claude+1

工具名
解决什么失败模式
为什么不是 Bash
为什么不是子代理
EnterWorktree
主分支/主目录直接改动风险太高；需要在隔离 worktree 里动手。
当然可以 git worktree add，但 Claude Code 要的是“会话知道自己已切换隔离环境”，还要接上 hooks、permissions、cleanup。
子代理解决的是“上下文隔离”；worktree 解决的是“文件系统/Git 隔离”。维度不同。
ExitWorktree
隔离环境如果没有显式退出点，会把会话状态搞混。
Bash 只能 cd 回来，不知道 Claude 的 worktree session 语义。
仍然是环境边界切换，不是认知分工。


把 35 个工具放在一起看，最有价值的 4 个结论



第一，Claude Code 不是把一切都收敛成 Bash。
他们刻意把“找上下文”“改文件”“跑命令”“盯后台”“管任务”“管代理”“管隔离环境”拆开，因为这些动作在 权限、状态、输出形状、是否需要阻塞主循环 上完全不同。工具名还能直接进 permission rules / hooks / subagent tool lists，这进一步证明 tool 设计本身就是系统设计。Claude+1


第二，Claude Code 也不是把一切都收敛成子代理。
Anthropic 用 subagent 的核心理由，是 保持主上下文干净，尤其是重文档搜索、辅助调查、并行任务；但像 AskUserQuestion、TaskUpdate、EnterPlanMode、EnterWorktree 这种，天然属于主循环的控制点，不适合外包。Claude


第三，工具会随着模型能力提升而被替换、降级、甚至删除。
官方亲口给了两个例子：TodoWrite 以前必要，后来开始约束模型；TaskOutput 则已经 deprecated，回退给 Read。这说明 Anthropic 的设计不是“多做工具”，而是“持续检查这个工具是否还在帮模型”。Claude+1


第四，Claude Code 真正在做的，是 agent 的 control surface。
ToolSearch 管的是 action space 膨胀，Task* 管的是 shared state，Agent / Team* / SendMessage 管的是 delegation，Monitor / Cron* 管的是时间和后台事件，EnterPlanMode / ExitPlanMode 管的是思考与行动之间的闸门。换句话说，Claude Code 的工具体系更像一个轻量 agent OS，而不是 IDE 功能菜单。Claude+3Claude+3Claude+3


你要的话，我下一条可以继续把这张表再升级成一版更“研究型”的矩阵：每个工具映射到它所属的设计原则（结构化 / 权限化 / 上下文化 / 会话化 / 协调化 / 隔离化），那样会更接近你想要的“Claude Code 内部对 TOOL 的严谨设计图谱”。
