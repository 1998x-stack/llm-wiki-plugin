## 五大不确定性降低机制

### 机制 1：单线程主循环（架构层）

```
解决的问题：多 Agent 状态竞争导致的不可预测行为

nO 主循环 = while(has_tool_calls) { execute → append_result }

设计收益：
  · 扁平消息历史 → 调试可读、行为可预测
  · 单线程执行 → 无状态竞争、无并发副作用
  · 自然终止条件 → 无需任意迭代上限（反模式）
```

### 机制 2：Hooks 确定性控制（执行层）

```
解决的问题：LLM 在长会话中忘记执行规则

"CLAUDE.md 写规则" → 概率性遵守（第 47 次会话可能跳过）
"PostToolUse Hook" → 确定性执行（每次写文件后强制 Lint）

核心：Prompts suggest, Hooks guarantee.
```

### 机制 3：上下文压缩 + CLAUDE.md（记忆层）

```
解决的问题：上下文窗口有限导致的信息丢失

短期记忆：上下文窗口（200k tokens）
    → 92% 时触发 Compressor wU2
    → 优先清除工具调用输出
    → 总结对话历史

长期记忆：CLAUDE.md + Markdown 记忆文件
    → 不受上下文窗口限制
    → 跨会话持久
    → 人类可读、可审计
```

### 机制 4：TodoWrite + Reminder 注入（规划层）

```
解决的问题：目标漂移（Goal Drift）

TODO 列表记录结构化任务状态：
    { id, content, status: "in_progress|completed|pending", priority }

每次工具调用后系统注入 Reminder：
    [SYSTEM REMINDER]
    ✅ task_001_a: 已完成
    🔄 task_001_b: 进行中（当前任务）
    ⏳ task_002: 待处理

效果：无论对话进行多少轮，Agent 始终"记得"完整任务地图。
```

### 机制 5：子 Agent 深度限制（并行层）

```
解决的问题：无限递归导致的 Agent 扩散和资源失控

规则：子 Agent 深度严格限制为 1
    主 Agent → Sub-Agent（allowed）
    Sub-Agent → Sub-Sub-Agent（blocked）

收益：
  · 并行能力不受限
  · 上下文隔离有效
  · 资源消耗可预测
  · 无递归爆炸风险
```

## 架构选择的权衡矩阵

| 维度 | Claude Code 的选择 | 放弃的方案 | 降低的不确定性 |
|------|------|------|------|
| 执行模型 | 单线程主循环 | 多 Agent 蜂群 | 状态竞争、行为不可预测 |
| 代码搜索 | GrepTool（正则）| 向量检索 | 近似匹配、索引漂移 |
| 长期记忆 | Markdown 文件 | 向量数据库 | 运维复杂性、检索失败 |
| 代码变更 | Diff 工作流 | 全文替换 | 不可审计的变更 |
| 并行控制 | 子 Agent 深度=1 | 无限递归 | Agent 扩散、资源失控 |
| 上下文管理 | 92% 触发压缩 | 被动截断 | 隐性上下文丢失 |
| 安全控制 | Hook 强制执行 | Prompt 建议 | 概率性跳过 |
| 外部集成 | MCP 统一协议 | 专用插件集成 | 集成碎片化、维护负担 |

## 生产级 Agent 反模式清单

| 反模式 | 后果 | 正确做法 |
|--------|------|---------|
| 用 Prompt 强制工具调用顺序 | LLM 可能跳过步骤 | 用 PreToolUse Hook + 编程前提条件 |
| 总结事务性事实（"客户想退款"）| 丢失金额、订单号等关键数据 | 持久化具体数字到事实块 |
| CI/CD 不加 `-p` 标志 | 作业无限期挂起 | 始终使用 `--print` 非交互模式 |
| 用提示词请求 JSON 输出 | 无法保证有效 JSON | 使用带 JSON Schema 的 `tool_use` |
| 无限制子 Agent 递归 | Agent 扩散，资源失控 | 严格深度限制为 1 |
| Token 硬编码在配置文件 | 机密泄露 | 环境变量 + `.gitignore` |
| 用概率 Hook 保护安全边界 | 偶发绕过 | 安全边界用 `command` 类型（确定性）|
| 单一巨型 CLAUDE.md | 信号被噪声淹没 | 三层架构：全局/项目/技能 |

## 工程哲学的本质

```
LLM 是概率性系统，不是"带有怪癖的确定性系统"。

驾驭概率性系统产生可靠结果的方式：
    在 LLM 决策之外，构建确定性的基于事件的强制执行层。

PreToolUse Hook 在每条 Bash 命令前机械地阻止 main 分支提交，
    无论模型记得什么、忘了什么、决定优先做什么。

这就是"Prompts suggest, Hooks guarantee"的本质。
```

## 对 RAG / Agent 系统的迁移原则

| Claude Code 机制 | RAG/Agent 系统的对应设计 |
|----------------|------------------------|
| nO 单线程主循环 | LangGraph 单一状态机（避免并发状态竞争）|
| Compressor wU2 | RAGFlow 分块压缩 + 摘要 |
| GrepTool（正则）| Neo4j Cypher 精确查询（非近似向量）|
| TodoWrite Reminder | LangGraph Checkpoint 状态持久化 |
| Hooks 确定性控制 | FastAPI 中间件 + LangGraph 强制边 |
| CLAUDE.md 三级层级 | 全局配置 → 项目 config → 模块 schema |
| 子 Agent 深度限制 | LangGraph 递归深度上限 |
| h2A 实时转向队列 | SSE 连接断开检测 + 优雅终止 |
| MCP 统一协议 | 统一 Tool Registry + 标准化 Schema |
