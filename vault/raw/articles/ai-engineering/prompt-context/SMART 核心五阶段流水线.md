**SMART 核心五阶段流水线**

[Synergizing Code Coverage and Gameplay Intent: Coverage-Aware Game Playtesting with LLM-Guided Reinf](https://arxiv.org/html/2512.12706v1)

**背景先说好**

游戏刚更了新：加了**「洋葱披萨」任务**，新增了面团、烤箱、撒洋葱逻辑，也改了一堆代码。

SMART 的任务：**让AI自动测这个更新，既要能正常做出披萨，又要把所有新改的代码都测一遍**。

**SMART 核心5阶段流水线（通俗版+举例）**

**阶段1：AST差异解析 ——【先找出：代码到底改了啥？】**

**大白话**：

把游戏更新**前、后**的代码对比一遍，像改作文找错别字一样，把**新增/修改的代码行、判断分支（if-else）**全部揪出来，标记成「必须测到的代码点」。

**举例子**：

更新加了披萨制作、烤箱烘烤、撒洋葱的代码，还有“披萨烤焦”“配料放错”的判断逻辑。

这一步把这些**代码行、分支**全部找出来，记成一堆「要测的代码锚点」。

**阶段2：语义子目标生成 ——【把大任务，拆成一步步小操作】**

**大白话**：

让大模型看懂「做洋葱披萨」这个大任务，**拆成玩家能一步步做的小步骤**，而且必须按顺序来。

**举例子**：

把「做洋葱披萨」拆成 7 个小目标：

1. 拿面团放柜台
2. 切番茄
3. 番茄+奶酪做成生披萨
4. 生披萨放进烤箱烤
5. 烤好装盘
6. 撒洋葱碎
7. 送到出餐口

**阶段3：语义奖励生成 ——【AI做完一步，就给一颗糖】**

**大白话**：

把上面的**每一步小目标**，变成AI能懂的**奖励规则**：

做完这一步 → 给奖励；没做完 → 没奖励；必须按顺序做。

**举例子**：

* 放好面团 → 给+10奖励
* 切好番茄 → 给+20奖励
* 烤好披萨 → 给+30奖励

AI为了拿奖励，就会乖乖**按流程做披萨**，不会瞎跑。

**阶段4：结构锚点映射 ——【哪一步操作，对应测哪段代码】**

**大白话**：

把「小步骤」和「代码锚点」**一一对应绑死**：

只有做到这一步时，才测这一步相关的代码，避免AI瞎测、乱测。

**举例子**：

* 步骤1「放面团」 ↔ 测【面团放置代码】
* 步骤4「烤披萨」 ↔ 测【烤箱烘烤/烤焦代码】
* 步骤6「撒洋葱」 ↔ 测【洋葱撒料代码】

没到烤披萨的时候，就不会去测烤箱代码，精准不浪费。

**阶段5：自适应混合奖励 ——【既要会玩，又要测全代码】**

**大白话**：

给AI**双重奖励**，这是 SMART 最牛的地方：

1. **语义奖励**：按步骤做完任务（保证能正常玩）
2. **结构奖励**：第一次测到新代码（保证代码全覆盖）

**举例子**：

* AI按流程做好披萨 → 拿**语义奖励**（保证功能正常）
* AI不小心触发了「披萨烤焦」「配料放错」的代码分支 → 拿**结构奖励**（保证代码都测到）

最后AI既会做披萨，又把所有新代码、边界情况全测了。

**一句话记住整个流水线**

1. 找改了哪些代码
2. 拆成一步步小任务
3. 每步做完给奖励
4. 哪步测哪段代码
5. 既会玩游戏，又测全代码
