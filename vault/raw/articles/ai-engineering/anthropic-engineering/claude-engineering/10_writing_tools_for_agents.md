# 为 Agent 撰写有效工具——用 Agent 完成

> **原文**：[Writing effective tools for agents — with agents](https://www.anthropic.com/engineering/writing-tools-for-agents)  
> **发布日期**：2025 年 9 月 11 日  
> **类别**：工具设计 · Agent 工程 · Meta-AI

## 摘要

本文介绍了一个引人入胜的 meta-AI 应用：用 AI Agent 来改进 AI Agent 使用的工具描述。通过让 Claude 反复测试有问题的工具并重写工具描述，Anthropic 发现工具描述质量的改进可使后续 Agent 的任务完成时间减少 **40%**。这是"AI 自我改进"在工程实践层面的一个具体体现。

---

## 一、工具描述质量的重要性

在 Agent 系统中，工具（Tool）是 LLM 与外部世界的接口。工具的性能不仅取决于底层实现，更依赖于**工具描述的质量**——这影响 Agent：
- 是否知道何时使用该工具
- 是否了解工具的正确参数格式
- 是否理解工具的限制和边界情况
- 是否能将工具与其他工具正确配合

**糟糕的工具描述可能导致**：
- 错误的工具选择（完全使用了错误的工具）
- 参数格式错误导致调用失败
- Agent 绕过有用工具的"死路"探索

---

## 二、工具测试 Agent 的设计

Anthropic 构建了一个"工具测试 Agent"，其工作流程：

```
输入：一个描述有问题的 MCP 工具

步骤 1：Agent 尝试使用该工具（多次，涵盖不同场景）
步骤 2：观察失败模式和不直观的行为
步骤 3：Agent 分析失败原因
步骤 4：Agent 重写工具描述以避免已发现的问题
步骤 5：循环 10+ 次以发现边缘情况

输出：改进后的工具描述 + 发现的关键细节和 Bug
```

## 三、有效工具描述的核心要素

### 3.1 工具的自包含性

好的工具描述应包含：
- **目的陈述**：这个工具做什么（1-2 句话）
- **使用示例**：典型调用的具体例子
- **边缘情况**：已知的特殊情形及处理方式
- **输入格式要求**：期望的数据类型、格式、约束
- **与其他工具的边界**：何时用这个工具而非类似工具

### 3.2 避免功能重叠

工具集的常见失败模式：功能相似的工具过多，Agent 无法确定使用哪个。

**判断标准**：如果有经验的人类工程师也无法立即判断应该用哪个工具，那 Agent 也无法。

### 3.3 poka-yoke 设计

通过接口设计使常见错误在结构上不可能发生：
- 使用具体类型而非宽泛的字符串
- 提供枚举值而非自由文本
- 要求绝对路径而非相对路径（Claude 在 SWE-bench 上的经验）

## 四、Meta-AI 改进循环的价值

工具测试 Agent 的实践揭示了一个更广泛的原则：**AI 可以改进 AI 使用的工件**。

这在实践中意味着：
1. 工具描述可以通过 AI 辅助迭代快速改善
2. Prompt 可以通过 AI 生成测试用例并分析失败来优化
3. Agent 策略可以通过 Agent 模拟来调试

量化结果：经过 AI 辅助优化的工具描述使后续 Agent 任务完成时间减少 **40%**——这证明了投资工具质量的 ROI。

---

## 五、实践建议

1. **运行大量示例**：在 Anthropic Workbench 或 Console 中运行 20+ 个示例输入，观察工具使用错误
2. **记录失败模式**：系统性记录 Agent 如何误用工具
3. **让 AI 重写描述**：提供失败案例，让 Claude 分析并改写工具描述
4. **测试-改写-重测循环**：不要在一次改写后停止，至少循环 5 次
