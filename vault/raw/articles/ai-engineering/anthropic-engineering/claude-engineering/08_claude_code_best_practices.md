## 摘要

本文是 Anthropic 官方发布的 Claude Code 使用指南，系统整理了跨越数百小时实战积累的工程最佳实践。核心主题围绕一个关键约束展开：**上下文窗口是最稀缺的资源**，所有最佳实践都服务于这一约束的有效管理。文章涵盖从环境配置、会话管理到自动化扩展的完整工作流。

---

## 一、核心约束：上下文窗口性能退化

Claude Code 所有最佳实践的底层逻辑只有一条：

> "LLM 在上下文填满时性能下降。上下文窗口是最重要的需要管理的资源。"

具体症状：
- 单次调试会话或代码库探索可能消耗数万 token
- 上下文填满时，Claude 开始"遗忘"早期指令
- 无关上下文积累会干扰重要指令

这一约束驱动了所有后续建议。

---

## 二、为 Claude 提供验证机制

**最高杠杆的单项操作**：提供验证标准（测试、截图、预期输出），让 Claude 能够自我检验。

### 实践对比

| 模糊指令 | 精确指令 |
|---|---|
| "实现一个验证邮箱的函数" | "写一个 validateEmail 函数。测试案例：user@example.com→true, invalid→false。实现后运行测试。" |
| "让仪表板看起来更好" | "[截图] 实现此设计，截图结果并与原始截图比较，列出差异并修复" |
| "构建失败了" | "构建报错：[粘贴错误]。修复并验证构建成功，解决根本原因，不要抑制错误" |

没有清晰的成功标准，Claude 可能产出看似正确实则不工作的代码，并且你成为唯一的反馈循环。

## 三、探索-规划-编码工作流

**分离研究与规划和实现，避免解决错误问题。**

推荐四阶段工作流：

```
阶段 1：探索（Plan Mode）
"读取 /src/auth 理解会话和登录处理方式，
 以及如何管理密钥的环境变量。"

阶段 2：规划（Plan Mode）
"我想添加 Google OAuth。哪些文件需要修改？
 会话流程是什么？创建计划。"
（Ctrl+G 可将计划在编辑器中打开直接编辑）

阶段 3：实现（Normal Mode）
"按计划实现 OAuth 流程，为回调处理器写测试，
 运行测试套件并修复失败。"

阶段 4：提交（Normal Mode）
"用描述性消息提交并开 PR"
```

**规划的适用场景**：
- 不确定方法时
- 修改多个文件时
- 对要修改的代码不熟悉时

**跳过规划的场景**：能用一句话描述 diff 时（修改拼写错误、添加日志行等）

## 四、CLAUDE.md：持久化上下文的核心

CLAUDE.md 是每次会话开始时 Claude 自动读取的特殊文件，是项目知识的持久化载体。

### 应该包含什么

```markdown
# 代码风格
- 使用 ES 模块（import/export）语法，不用 CommonJS（require）
- 尽量解构导入

# 工作流
- 完成一系列代码修改后务必进行类型检查
- 运行单个测试而非整个测试套件以提高性能
```

### 不该包含什么

| ✅ 包含 | ❌ 不包含 |
|---|---|
| Claude 无法猜到的 Bash 命令 | Claude 通过读代码就能弄明白的信息 |
| 区别于默认的代码风格规则 | Claude 已知的标准语言惯例 |
| 测试指令和首选测试运行器 | 详细 API 文档（提供链接即可） |
| 分支命名、PR 规范等约定 | 频繁变化的信息 |

**关键原则**：CLAUDE.md 过长 → Claude 开始忽视它。对每行提问："删除这行会导致 Claude 犯错吗？"若不会，删除它。

## 五、上下文管理策略

### 主动清理

- `/clear`：在不相关任务之间重置上下文
- `/compact <指令>`：自定义压缩（如 `/compact 聚焦在 API 变更上`）
- Esc+Esc 或 `/rewind`：恢复到检查点
- `/btw`：侧边问题（不进入对话历史，不消耗上下文）

### 子 Agent 用于调查

```
"用子 Agent 调查我们的认证系统如何处理 token 刷新，
 以及我是否有任何现有的 OAuth 工具可以复用。"
```

子 Agent 在独立上下文中探索代码库，只将摘要返回给主对话。

### 经验法则

- 同一问题纠错 2 次以上 → 清理上下文，重写更精确的 prompt
- 探索导致 Claude 读取大量文件 → 用子 Agent 隔离探索上下文

## 六、自动化与扩展

### 非交互模式

```bash
# 单次查询
claude -p "解释这个项目做什么"

# 结构化输出
claude -p "列出所有 API 端点" --output-format json

# CI/CD 集成
claude -p "修复所有 lint 错误" --permission-mode auto
```

### 并行会话与文件扩展

```bash
# 批量迁移示例
for file in $(cat files.txt); do
  claude -p "将 $file 从 React 迁移到 Vue。返回 OK 或 FAIL。" \
    --allowedTools "Edit,Bash(git commit *)"
done
```

### Writer/Reviewer 模式

```
会话 A（Writer）              会话 B（Reviewer）
实现 API 限流中间件
                              审查 @src/middleware/rateLimiter.ts
                              寻找边界情况、竞争条件
修复 B 的反馈
```

## 七、常见失败模式

1. **厨房水槽会话**：在一个会话中混合无关任务 → 用 `/clear` 分隔
2. **反复纠错**：同一问题纠错多次 → 清空重来，写更好的初始 prompt
3. **CLAUDE.md 过度膨胀**：重要规则被噪声淹没 → 定期精简
4. **相信验证间隙**：Claude 产出看似正确但实则有问题的实现 → 始终提供验证机制
5. **无边界探索**：要求 Claude "调查"某事物而无范围 → 限定范围或使用子 Agent

---

## 八、结论

Claude Code 最佳实践的核心是**上下文经济学**：把宝贵的注意力预算用在最重要的信息上，通过 CLAUDE.md 积累知识，通过 `/clear` 和子 Agent 控制噪声，通过验证机制确保质量。

这些实践不是孤立技巧，而是服务于同一个目标：让 Claude Code 成为一个可靠、可预测的工程合作伙伴。
