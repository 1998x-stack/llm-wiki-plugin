在 Claude Code 中，管理会话、上下文和压缩的方式对结果的影响超乎你的想象。本指南将为你提供在每个关键时刻做出正确选择的实用建议。

---

Anthropic 发布了 **`/usage`** ，一个新的斜杠命令，帮助你了解你在 Claude Code 中的使用情况。这个功能是根据我们与客户的多次对话开发的。

在这些通话中反复出现的一个问题是，用户在管理会话方面存在很大差异，尤其是在 Claude Code 的上下文更新到 1M 之后。

你是只使用一两个在终端中保持打开的会话吗？你是每次使用新 提示词 (prompt) 时都开启一个新会话吗？你何时使用 [压缩 (compact)](https://link.zhihu.com/?target=https%3A//platform.claude.com/docs/en/build-with-claude/compaction) 、回溯 (rewind) 或 [子智能体 (subagents)](https://link.zhihu.com/?target=https%3A//code.claude.com/docs/en/sub-agents) ？是什么导致了糟糕的压缩或糟糕的会话？

这里面有许多出人意料的细节，它们可以真正地塑造你使用 [Claude Code](https://link.zhihu.com/?target=https%3A//code.claude.com/docs/en/overview) 的体验，而几乎所有这些细节都源于 [对上下文窗口的管理](https://link.zhihu.com/?target=https%3A//code.claude.com/docs/en/how-claude-code-works) 。

### 关于上下文、压缩和上下文退化的快速入门

![](https://pic3.zhimg.com/v2-326234c711d87d322e660f0e129622be_1440w.jpg)

上下文窗口是模型在生成下一个响应时能够一次性“看到”的所有内容。它包括你的系统 提示词 (system prompt)、到目前为止的对话、每次的工具调用及其输出，以及所有已读取的文件。Claude Code 拥有一个 1M Token 的上下文窗口。

不幸的是，使用上下文会对性能产生轻微影响，这通常被称为上下文退化 (context rot)。上下文退化是一种观察到的现象，即随着上下文的增长，模型性能会下降，因为注意力被分散到更多的 Token 上，而陈旧、不相关的内容开始干扰当前任务。

上下文窗口是一个硬性截断，所以当你接近上下文窗口的末尾时，你正在处理的任务会被自动总结成一个更小的描述，然后模型在一个新的上下文窗口中继续工作。我们称之为压缩 (compaction)。你也可以自己触发压缩。

![](https://picx.zhimg.com/v2-59815e13c4df1281e556c9ab462abf89_1440w.jpg)

### 每一次交互都是一个分支点

假设你刚刚让 Claude 完成了一项任务——现在你的上下文中已经有了一些信息（工具调用、工具输出、你的指令），接下来你有多种出人意料的选择：

- **继续 (Continue)** — 在同一会话中发送另一条消息
- **`/rewind` (esc esc)** — 跳回到之前的某条消息，并从那里重试
- **`/clear`** — 开始一个新会话，通常使用你刚从之前内容中提炼出的简要说明
- **压缩 (Compact)** — 总结到目前为止的会话，并在总结的基础上继续进行
- **子智能体 (Subagents)** — 将下一块工作委托给一个拥有自己干净上下文的智能体，并只将它的结果拉回来

虽然最自然的做法是直接继续，但其他四个选项的存在是为了帮助你管理上下文。

![](https://pic3.zhimg.com/v2-afbbc66cef9216e9ab333b312d781cb0_1440w.jpg)

### 何时开启新会话

你应该保留一个长期运行的会话，还是开启一个新会话？我们的一般经验法则是，当你开始一个新任务时，也应该开始一个新会话。

虽然 1M 的上下文窗口意味着你现在可以更可靠地执行更长的任务，例如从头开始构建一个全栈应用，但上下文退化仍可能发生。

有时你可能会执行一些相关任务，其中部分上下文仍然是必要的，但并非总是如此。例如，为你刚刚实现的功能编写文档。虽然你可以开始一个新会话，但 Claude 将不得不重新读取你刚刚实现的文件，这会更慢、更昂贵。

### 使用回溯而非纠正

![](https://pica.zhimg.com/v2-dadcc3b231b189d5a67a3f0dec291efa_1440w.jpg)

在 Claude Code 中，双击 Esc 键（或运行 `/rewind` ）可以让你跳回到之前的任何一条消息，并从那里重新提供 提示词。该时间点之后的消息将从上下文中被丢弃。

回溯 (Rewind) 通常是比纠正更好的方法。例如，Claude 读取了五个文件，尝试了一种方法，但没有成功。你的本能反应可能是输入“那个方法不行，试试 X”。但更好的做法是回溯到刚读取完文件之后，然后用你学到的新信息重新提供 提示词。“不要用方法 A，foo 模块没有暴露那个接口——直接用方法 B。”

也可以使用 *“从这里开始总结”* 或 `/rewind` 斜杠命令，让 Claude 总结其学到的内容并创建一条交接消息，这有点像一个尝试了某事但失败了的“未来自己”给“过去的 Claude”迭代版本发的消息。

### 压缩 vs. 启动新会话

一旦会话变得很长，有两种方法来去除无关的上下文： `/compact` 或 `/clear` （然后重新开始）。它们感觉相似，但行为却大相径庭。

**压缩 (Compact)** 会要求模型总结到目前为止的对话，然后用该摘要替换历史记录。这是有损的，但你不需要自己编写任何东西，而且 Claude 可能会更全面地包含重要的学习成果或文件。你还可以通过传递指令来引导它 (`/compact focus on the auth refactor, drop the test debugging`)。

![](https://pic3.zhimg.com/v2-ce3ce6673fee5e4c6ce06e1459bfb174_1440w.jpg)

使用 `/clear` 时，你可以自己写下重要的内容（“我们正在重构认证中间件，约束是 X，相关文件是 A 和 B，我们已经排除了方法 Y”），然后干净地开始。这需要更多的工作，但最终的上下文是你自己决定认为相关的部分。

### 是什么导致了糟糕的自动压缩？

如果你运行许多长期会话，你可能已经注意到有时压缩的效果会特别差。在这种情况下，我们经常发现，当模型无法预测你的工作方向时，就可能发生糟糕的压缩。

在上面的例子中，自动压缩 (autocompact) 在一个漫长的调试会话后触发，并总结了调查过程，而你的下一条消息是“现在修复我们在 bar.ts 中看到的另一个警告”。

但由于该会话的重点是调试，另一个警告可能已从摘要中被丢弃。

这一点尤其困难，因为由于上下文退化，模型在进行压缩时正处于其最不智能的状态。拥有 1M 上下文，你有更多时间通过描述你想做的事情来主动使用 `/compact` 。

### 子智能体与全新的上下文窗口

[子智能体 (Subagents)](https://link.zhihu.com/?target=https%3A//claude.com/blog/subagents-in-claude-code) 在你预先知道某项工作会产生大量你不再需要的中间输出时，往往效果很好。

当 Claude 通过 Agent 工具生成一个子智能体时，该子智能体会获得自己全新的上下文窗口。它可以根据需要完成任意多的工作，然后综合其结果，这样只有最终报告会返回给父级。

![](https://pic2.zhimg.com/v2-46f1b353d572670c1ef9f618ce4b5627_1440w.jpg)

我们在 Anthropic 内部使用的心智测试是： *我将来还会需要这个工具的输出，还是只需要结论？*

虽然 Claude Code 会自动调用子智能体，但你可能希望明确地指示它这样做。例如，你可能想告诉它：

- “启动一个子智能体，根据以下规范文件来验证这项工作的结果”
- “派生一个子智能体，通读另一个代码库并总结其认证流程的实现方式，然后你自己以同样的方式实现它”
- “派生一个子智能体，根据我的 git 变更来编写这个功能的文档”

### 总结

为了帮助你选择使用哪种上下文管理功能，我们整理了下面这个有用的表格，概述了常见情况、应使用哪种工具以及原因。

| 情况 | 建议使用 | 原因 |
| --- | --- | --- |
| 同一任务，上下文仍然相关 | 继续 (Continue) | 窗口中的所有内容仍是有效的；不要为重建它而付费。 |
| Claude 走错了路 | 回溯 (Rewind) (双击 Esc) | 保留有用的文件读取，放弃失败的尝试，用学到的新知识重新提供 提示词。 |
| 任务进行中，但会话因过时的调试/探索而变得臃肿 | /compact <hint> | 低工作量；Claude 决定哪些内容是重要的。如果需要，可以用指令引导它。 |
| 开始一个真正的新任务 | /clear | 零退化；精确控制哪些内容被继承下来。 |
| 下一步将产生大量输出，但 你只需要其结论（代码库搜索、验证、文档编写） | 子智能体 (Subagent) | 中间的工具噪音保留在子智能体的上下文中；只有结果会返回。 |
