**2. 实验一详细分析：CLIP 图像通道融合**

**2.1 问题定义**

v12 通道判别力分析发现 CLIP 图像通道的判别力为**负值**（correct\_mean=0.438 < wrong\_mean=0.461）。这意味着正确答案的 CLIP 相似度反而低于错误答案。假设：多视角信息的不同融合方式可能改善这一问题。

**2.2 四种融合方法**

|  |  |  |  |
| --- | --- | --- | --- |
| 方法 | 公式 | FAISS 索引大小 | 搜索方式 |
| **Original (max-score)** | FAISS 存 4×N 向量，搜索时 max(sim across 4 views) | 2628 vectors (4×657) | 多向量 max 聚合 |
| **Mean Pooling** | emb = mean(view\_default, view\_front, view\_side, view\_top) | 657 vectors | 单向量直接搜索 |
| **Weighted Mean** | emb = 0.4×default + 0.3×front + 0.2×side + 0.1×top | 657 vectors | 单向量直接搜索 |
| **Element-wise Max** | emb[i] = max(view\_default[i], view\_front[i], view\_side[i], view\_top[i]) | 657 vectors | 单向量直接搜索 |

**2.3 判别力对比**

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| 融合方法 | Correct Mean | Wrong Mean | Gap | Power |
| Original (max-score) | 0.4377 | 0.4613 | -0.0236 | 0.01 |
| Mean Pooling | 0.4393 | 0.4623 | **-0.0230** | 0.01 |
| Weighted Mean | 0.4395 | 0.4618 | **-0.0223** | 0.01 |
| Element-wise Max | 0.3958 | 0.4216 | -0.0258 | 0.01 |

**分析**:

* 所有方法的 gap 都是**负值**，范围 -0.022 ~ -0.026，差异极小
* Weighted Mean 的 gap 最小（-0.0223），但改善幅度仅 0.001
* Element-wise Max 反而最差（gap=-0.0258），原因是逐元素取最大值后的向量偏离了原始语义空间
* Power 全部被截断为 0.01（负值 → 最低值），最优 IMG 权重都是 0.02

**2.4 Pipeline 指标对比**

**默认权重（BM25=0.53, TEXT=0.45, IMG=0.02）**:

|  |  |  |  |  |  |  |
| --- | --- | --- | --- | --- | --- | --- |
| 融合方法 | UUID Hit@1 | UUID MRR | Name Hit@1 | Name MRR | Bad(UUID) | True-Bad |
| Original (max-score) | 0.7422 | 0.8177 | 0.8438 | 0.8890 | 15 | 9 |
| **Mean Pooling** | 0.7422 | **0.8204** | 0.8359 | 0.8878 | **14** | **8** |
| Weighted Mean | 0.7344 | 0.8177 | 0.8359 | 0.8885 | 14 | 9 |
| Element-wise Max | 0.7266 | 0.8127 | 0.8359 | 0.8870 | 14 | 9 |

**最优权重（BM25=0.53, TEXT=0.45, IMG=0.02 — 与默认相同）**:

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| 融合方法 | UUID Hit@1 | UUID MRR | Name Hit@1 | Name MRR |
| Original (max-score) | 0.7500 | 0.8243 | 0.8594 | 0.9001 |
| **Mean Pooling** | 0.7500 | **0.8263** | 0.8438 | 0.8921 |

**2.5 结论**

**CLIP 图像融合实验的核心结论是：在图像权重仅 0.02 的情况下，融合方法的选择对最终搜索质量几乎没有影响。**

* Mean Pooling 在 UUID MRR 上略优（0.8204 vs 0.8177），但差距仅 +0.003
* 4 种方法之间的 MRR 极差仅 0.0077（0.8127~0.8204），不具备统计显著性
* 根本原因：CLIP text-to-image 跨模态匹配的精度瓶颈在模型本身，而非多视角信息的聚合方式
* **建议**: 保持 Original (max-score) 或 Mean Pooling 均可，无需进一步优化图像融合

**3. 实验二详细分析：Reranker 速度优化**

2. 换用更快模型（qwen3.5-plus → qwen-turbo）

**反直觉发现: 候选数越少，排序质量越好。**

原因分析：

1. **信息密度**: 10 个候选的 prompt 比 30 个更精炼，LLM 更容易识别最相关的候选
2. **噪声干扰**: K=30 中后 20 个候选大多是低相关度的干扰项，可能误导 LLM 的排序判断
3. **注意力分散**: LLM 在面对更长的候选列表时，注意力分配更均匀，可能错过关键差异
4. **RRF 初排已足够**: 3-channel RRF 的 top-10 已经包含了大部分正确答案（Hit@10 > 90%），扩大到 top-30 引入的主要是噪声而非正确答案

**4. 实验三详细分析：双轨评估**

**4.1 问题定义**

游戏资产库中 379 个唯一名称对应 657 个 UUID，其中 87 个名称有多个变体 UUID。典型例子：

|  |  |  |
| --- | --- | --- |
| 名称 | UUID 数量 | 说明 |
| 绿叶大树 | 40 | 40 棵外观略有差异的绿叶大树 |
| 木栅栏 | 12 | 12 种不同长度/样式的木栅栏 |
| 石柱 | 8 | 8 种不同纹理的石柱 |
| 绿冠大树 | 35 | 35 棵绿冠大树变体 |

当用户搜索"绿叶大树"时，返回任何一棵绿叶大树都应算正确。但 UUID-strict 只认标注的特定 UUID。

**4.2 整体指标对比**

|  |  |  |  |  |

**Hit@1 的差距最大（+13.8%）**: 因为 top-1 最容易被同名变体"误杀"——如果标注的 UUID 排在第 2 位但第 1 位是同名变体，UUID-strict 判为 miss 但 Name-based 判为 hit。

**6. 未来优化方向**

基于 v13 的实验结果，按优先级排列：

**6.1 高优先级**

1. **测试集标注修正**: 9 个 true-bad 中至少 3 个可能是标注问题（查询与期望答案矛盾），修正后 Name-based MRR 可能接近 0.92+
2. **树类/建筑类资源区分度增强**: CAT-06 是最弱类别（Name MRR=0.57），大量同名树资源难以区分，考虑在描述中增加更多区分性特征
3. **Name-based 评估作为主指标**: 实验证明 Name-based 更准确地反映搜索质量，建议作为正式评估标准

**6.2 中优先级**

1. **更强的 Reranker 模型**: 当前 qwen3.5-plus 的上限约在 MRR=0.82-0.83，更强的模型（如 qwen-max 或 Claude）可能进一步提升
2. **BM25 通道强化**: BM25 贡献最大权重（0.53），优化同义词词典或使用语义扩展的 BM25 可能有空间
3. **查询分类+差异化策略**: 对极度模糊的查询（"那种大树"）考虑返回"请更具体描述"而非强行排序

**6.3 低优先级**

1. **CLIP 图像通道**: v13 已证明融合方法优化 ROI 极低，除非换用更强的跨模态模型（如 CLIP-L/14 或 SigLIP）
2. **更多 Reranker 候选数实验**: K=10 已是最优，K=5 可能过少，K=10 大概率是甜蜜点
