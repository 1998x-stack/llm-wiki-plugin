## 0. 一个不寻常的开源项目

2026 年 4 月，GitHub 上出现了一个名为 **mempalace** 的仓库，48 小时内冲上 7000+ Star，一周内突破 11000。

让所有人惊讶的不是数字，而是仓库的 owner：**Milla Jovovich**——《第五元素》里的 Leeloo，《生化危机》系列里的 Alice。

> 一个好莱坞 A 级女演员，为什么在 GitHub 上开源 AI 内存系统？

答案藏在她的 Instagram 视频里：她每天大量使用 ChatGPT 和 Claude，积累了数千次对话——创意决策、业务推演、项目调试。但每次打开新会话，AI 就像患了失忆症。所有的上下文、所有的推理链，全部蒸发。

她试过 Mem0、Zep 等主流工具，发现它们都有同一个根本缺陷：**让 AI 来决定该记什么**。AI 提取出"用户偏好 Postgres"，然后把当时为什么选择 Postgres 的那段推理全部丢掉。而她最需要的，恰恰是那段推理。

于是她找来工程师 Ben Sigman，用 Claude Code 协作开发，几个月后交出了 MemPalace v3.0.0。

## 1. MemPalace 是什么？

MemPalace 是一个**本地运行、完全开源的 AI 长期记忆系统**，核心理念只有一句话：

> **存储一切，然后让它变得可以被找到。**

与 Mem0、Zep 的设计哲学相反，MemPalace 不做任何 AI 摘要、不做信息提取、不让模型决定什么值得记忆。它的策略是：

| 维度 | 传统方案（Mem0 / Zep） | MemPalace |
|------|----------------------|-----------|
| 存储方式 | AI 提取关键信息 | 原文逐字存储 |
| 索引结构 | 平铺向量数据库 | 分层宫殿结构 |
| 运行环境 | 依赖云 API | 完全本地 |
| 信息损耗 | 提取时丢失推理链 | 零损耗 |
| LLM 调用 | 写入/读取时频繁调用 | 内存层零 LLM 调用 |

## 2. 核心设计哲学：不要让 AI 决定记什么

这是 MemPalace 最反直觉的地方，也是它最重要的洞见。

### 2.1 信息提取的代价

当你告诉 Mem0 一段对话：

```
用户：我们最终决定用 GraphQL 而不是 REST，主要是因为前端团队提出了三个痛点：
1. 多端适配需要不同的字段集合
2. 过度拉取导致移动端性能下降  
3. 接口版本管理成本太高

我们讨论了两个小时，权衡了 N+1 问题，最终认为用 DataLoader 可以解决...
```

Mem0 可能提取出：`用户偏好 GraphQL`

这一条信息存活了，但**三个痛点、两小时讨论、DataLoader 决策——全部消失**。下次你问"为什么我们用 GraphQL"，AI 无法还原当时的推理过程。

### 2.2 MemPalace 的答案：保留原文，结构化检索

MemPalace 把那段对话完整切块，存进 ChromaDB。检索时，向量语义搜索会根据问题找到最相关的原始片段，交还给 AI。AI 拿到的是完整的推理链，而不是一条被压扁的结论。

**96.6% 的 LongMemEval Recall@5 成绩，正是从这个"反直觉的简单"中来的。**

## 3. 技术选型：为什么只需要两个依赖

MemPalace 的 `requirements.txt` 极为克制：

```
chromadb
pyyaml
```

仅此而已。

- **ChromaDB**：本地向量数据库，负责嵌入存储与语义检索
- **PyYAML**：配置文件解析

没有 LangChain，没有 LlamaIndex，没有 OpenAI SDK，没有任何云服务依赖。所有的 Room 检测、内容分类、压缩，全部用正则表达式和关键词评分完成。

这不是技术局限，而是刻意为之的设计原则：**内存层应该是确定性的、免费的、离线的。**

## 6. 快速上手（5 行命令）

```bash
pip install mempalace

# 初始化项目
mempalace init ~/projects/myapp

# 挖掘代码和文档
mempalace mine ~/projects/myapp

# 挖掘对话记录
mempalace mine ~/chats/ --mode convos

# 搜索任何你讨论过的内容
mempalace search "为什么我们切换到 GraphQL"
```

## 7. 一句话总结

MemPalace 的核心论点是：**过去十年 AI 记忆领域一直在过度工程化提取层，而忽视了"把原文存好，然后找到它"这个更简单、更有效的路径。**

这个论点，用 96.6% 的基准分数做了背书。
