# Q: WASM 是什么？

根据提供的 Wiki 页面内容，**WASM**（全称 **WebAssembly**）是一种用于 Web 平台及跨平台编译目标的技术标准。以下是基于文档内容的详细解释：

### 1. 定义与核心能力
*   **跨平台编译目标**：WASM 允许将代码（如 C++）编译为可以在浏览器中运行的高效二进制格式。
*   **高性能计算**：旨在挖掘 Web 平台的最大性能潜力，提供接近原生的计算性能。
*   **指令集支持**：支持 **SIMD**（单指令多数据）指令集，能够利用浏览器底层的 SIMD 加速进行向量运算。
*   **多线程支持**：通过 `SharedArrayBuffer` 和 Worker 线程支持多线程并行计算（需配合特定的 HTTP 响应头配置）。

### 2. 在 UrhoX 引擎中的应用
在 UrhoX 引擎中，WASM 主要用于实现 Web 端游戏的高性能运行，具体包括：
*   **物理引擎并行化**：通过启用 WASM 的多线程和 SIMD 支持，使得 **Bullet Physics** 物理引擎能够在 Web 环境中利用多线程进行碰撞检测和约束求解，显著提升大规模物理模拟场景下的帧率。
*   **数学运算加速**：启用 `-msimd128` 等编译标志后，底层的向量（`btVector3`）、矩阵（`btMatrix3x3`）和变换运算性能可提升 **2x - 4x**。

### 3. 技术约束与配置
*   **编译器**：通常使用 **Emscripten** 进行编译。
*   **关键编译标志**：
    *   `-msimd128`：启用 128位 SIMD 指令集。
    *   `-pthread`：启用多线程支持。
    *   `-sPTHREAD_POOL_SIZE=4`：预分配 Worker 线程池。
*   **服务器配置要求**：为了在 Web 端安全地运行多线程 WASM，Web 服务器必须返回以下 HTTP 响应头：
    *   `Cross-Origin-Opener-Policy: same-origin`
    *   `Cross-Origin-Embedder-Policy: require-corp`
    *   *否则会出现 `SharedArrayBuffer is not defined` 错误。*

### 4. 局限性
*   **单线程事件循环限制**：尽管支持多线程，但 WASM 的主线程仍受限于单线程事件循环。如果在主线程进行同步阻塞等待（spin-wait），会导致异步回调无法触发，从而造成**死锁**。因此，WASM 环境下严禁使用同步阻塞式的资源下载或操作。
