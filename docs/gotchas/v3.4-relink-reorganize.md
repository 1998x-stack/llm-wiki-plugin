# Gotchas — v3.4 (relink + reorganize-raw)

## #28 — relink.py: substring matching, not word-boundary

**Status**: Documented (by design)

`relink.py` uses `str.find()` for term matching, not regex word-boundary `\b`. This means:
- "RRT" matches inside "RRT-Connect" even though "RRT-Connect" is a separate page
- Longest-match-first mitigates: "RRT-Connect" (10 chars) is processed before "RRT" (3 chars), so the longer term wins at overlapping positions
- But if text says "RRT 和 RRT-Connect", "RRT-Connect" consumes chars 4-14, then "RRT" correctly links chars 0-3

**When it bites**: A 2-char term like "QR" could match inside "QR算法" where "QR算法" is a separate page. Again, longest-match-first handles this — "QR算法" wins. But "QR" could match in unrelated text like "IQR" or URLs.

**Workaround**: Keep `MIN_TERM_LEN = 2` to avoid single-char noise. For truly problematic short terms, don't add them as aliases.

## #29 — relink.py: bold/italic markers split by links

**Status**: Documented (acceptable)

If text contains `**矩阵理论**`, relink produces `**[[矩阵理论]]**` which renders correctly in Obsidian (bold link). But `**矩阵**分析` becomes `**[[矩阵]]**分析` — also correct. The bold markers are not "protected zones" because they're inline formatting, and Obsidian handles `**[[link]]**` fine.

## #30 — relink.py: idempotent but hooks still fire

**Status**: Documented

Running `relink` a second time adds 0 new links (idempotent), but if wiki pages were modified in the first run, the PostToolUse hooks (lint, BM25, graph) will fire for every modified page. On 244 pages, this causes ~732 hook invocations. The hooks themselves are idempotent, but execution takes time.

**Mitigation**: Run relink BEFORE reindex/build in the maintain pipeline (already done), so hooks are batched with the subsequent build step.

## #31 — reclassify_raw.py: macOS case-insensitive filesystem

**Status**: Fixed

On macOS (HFS+/APFS), `raw/articles/AI-Papers` and `raw/articles/ai-papers` are the same directory. The script's idempotency check `new_folder.lower().startswith(old_folder.lower() + "/")` uses case-insensitive comparison to handle this. Without this, re-running after reorganization would re-match already-organized parent folders and try to move files into subdirectories of themselves.

## #32 — reclassify_raw.py: re-map.json is Claude-generated, not hardcoded

**Status**: Documented

Unlike earlier versions where `FOLDER_MAP` was hardcoded in Python, `re-map.json` is now generated by Claude during `wiki:reorganize-raw` execution. This means:
- The JSON must be written by Claude BEFORE running the script
- If `raw/re-map.json` doesn't exist, the script exits with `{"status": "error"}`
- The script validates folder existence at runtime — stale entries in re-map.json are silently skipped

## #33 — relink.py: `## 来源` protection boundary

**Status**: Documented

The protected zone starts at `## 来源` and extends to EOF. This means if a page has sections AFTER `## 相关` (rare but possible), those sections are also protected and won't get links. This is intentional — `## 来源` and `## 相关` contain structured reference data that should not be modified by auto-linking.

## #34 — maintain.md: lint step removed from pipeline

**Status**: Documented (intentional)

The maintain pipeline changed from `reindex → check → lint → build` to `reorganize-raw → relink → reindex → check → build`. The explicit `lint` step was removed because:
- `wiki:check` already runs `lint_wiki.py --json` for diagnostics
- Auto-repair (lint's job) is better done as a separate `wiki:lint` invocation when needed
- Relink now handles the main linking quality improvement that lint partially addressed

`wiki:lint` still exists as a standalone command for manual use.
