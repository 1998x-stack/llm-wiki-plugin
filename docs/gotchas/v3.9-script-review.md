## #38 — ingest-loop.md: hardcoded `/Users/mx/` path in subagent prompt

**Status**: Fixed (2026-04-16)

`ingest-loop.md` line 125 contained a hardcoded absolute path from a different user/machine (`/Users/mx/Desktop/series/核心项目系列/llm-wiki/vault`). Any subagent using this prompt template would get the wrong working directory.

**Fix**: Replaced with placeholder `{VAULT_DIR 的绝对路径，即当前工作目录}` so the command fills it dynamically.

## #39 — setup-ingest-loop.sh: YAML newline missing before `current_index`

**Status**: Fixed (2026-04-16)

Line 58 concatenated `$(echo -e "$FILES_YAML")current_index: 0` without a newline separator, producing invalid YAML:

```yaml
files:
  - "file1.md"
  - "file2.md"current_index: 0   # ← invalid: key stuck to last array element
```

The Qwen variant (`setup-ingest-loop-qwen.sh` line 64) already had the correct newline. Only the Claude variant was broken.

**Fix**: Added newline between `$FILES_YAML` expansion and `current_index:`.

**Same file, #40**: `python3 -c "...('$file', '$VAULT_DIR')"` string interpolation — single quotes in filenames would break the command. Fixed to use `sys.argv` argument passing.

## #40 — setup-ingest-loop.sh: unsafe single-quote injection in python3 -c

**Status**: Fixed (2026-04-16)

Line 34 used string interpolation to pass file paths into an inline Python command:

```bash
rel=$(python3 -c "import os; print(os.path.relpath('$file', '$VAULT_DIR'))")
```

If `$file` contained a single quote (e.g. `it's-a-file.md`), the Python command would be syntactically broken.

**Fix**: Changed to argument passing via `sys.argv`:

```bash
rel=$(python3 -c "import os,sys; print(os.path.relpath(sys.argv[1], sys.argv[2]))" "$file" "$VAULT_DIR")
```

## #41 — split_chat_json.py: source JSON deleted before verifying writes

**Status**: Fixed (2026-04-16)

`split_chat_json.py` line 108 called `os.remove(json_path)` unconditionally after the split loop. If any markdown file write failed silently (disk full, permission error), the source JSON was permanently lost with no backup.

**Fix**: Added write verification — checks all output files exist and are non-empty before deleting source. If verification fails, source JSON is kept and a warning is printed.

## #42 — build_maps.py: hardcoded subdirectory list

**Status**: Fixed (2026-04-16)

`build_maps.py` line 35 hardcoded `["concepts", "entities", "syntheses", "qa-insights"]` instead of using `WIKI_SUBDIRS` from `wiki_utils.py`. If a new subdirectory was added to the constant, `build_maps` would silently miss those pages.

**Fix**: Imported and used `WIKI_SUBDIRS` from `wiki_utils`.

## #43 — All hooks: JSON parse errors silently swallowed

**Status**: Fixed (2026-04-16)

All three PostToolUse hooks (`hook_bm25.sh`, `hook_lint.sh`, `hook_graph.sh`) used `2>/dev/null` when parsing stdin JSON, meaning any parse failure (malformed input, stdin format change) would silently set `FILE_PATH=""` and exit without logging.

**Fix**: Changed `2>/dev/null` to `2>>"$LOG"` so parse errors are appended to `log.hook.md` instead of discarded.
